配置包是服务方按贵司环境整理并单独交付的一个文件，里面有公司火山引擎对象存储（TOS）的地址、区域、桶名、目录前缀、访问密钥和公司名。把它导入后，智通数工AI 就能在您的电脑上直接读写公司的存储桶（下文简称"公司存储桶"）。每台电脑、每位使用者导入一次。

## 配置包是什么

- 形式：一个 `.zip`，或单独的 `zhitong.config.json` 文件。
- 来源：服务方交付。它**不随安装包分发**，本站也不提供下载。
- 内容含**明文访问密钥**，请像对待密码一样对待它：导入后从"下载"文件夹删除，不要转发，不要放进共享盘。

### 里面有什么

| 部分 | 内容 | 是否必有 |
|---|---|---|
| 公司 | 公司名称，导入成功时会显示 | 必有 |
| 存储桶连接 | 地址（如 `tos-cn-beijing.volces.com`）、区域（如 `cn-beijing`）、桶名、公司目录前缀 | 必有 |
| 存储桶密钥 | 访问密钥 ID 与访问密钥（俗称 AK/SK） | 必有 |
| SSH 主机 | 服务器别名、地址、端口、登录用户，可选私钥 | 只有需要火山引擎运维的人员才有 |
| 火山引擎 ve 配置名 | `ve` 命令行工具的配置名与区域；**不含** `ve` 的密钥 | 只有需要火山引擎运维的人员才有 |

文件内部格式如下（示例，密钥用 `…` 代替）。您不需要自己编辑它；格式有错时请让服务方重发。

```json
{
  "format": "zhitong.config/1",
  "company": { "name": "某某工程造价咨询有限公司" },
  "tos": {
    "endpoint": "tos-cn-beijing.volces.com",
    "region": "cn-beijing",
    "bucket": "zt-company",
    "prefix": "某某咨询",
    "accessKeyId": "AKLT…",
    "secretAccessKey": "…"
  }
}
```

## 导入步骤

::: steps
1. 打开智通数工AI，新建会话，确认预设是"智通数工AI"。
2. 把配置包文件拖进对话框，发送"导入这个配置包"。
3. 它调用导入工具 `config_import`：先检查格式，再把密钥存进本机凭据存储，把桶的连接设置写进本机配置。工具结果示例：

   ```text
   已导入「某某工程造价咨询有限公司」的配置包：tos://zt-company/某某咨询/（tos-cn-beijing.volces.com，cn-beijing）。密钥已存入本机凭据存储（ZT_TOS_ACCESS_KEY_ID、ZT_TOS_SECRET_ACCESS_KEY），TOS 工具已按新设置重新加载。
   ```

   结果里的 `ZT_TOS_ACCESS_KEY_ID`、`ZT_TOS_SECRET_ACCESS_KEY` 是密钥在凭据存储里的名字，不是密钥本身。
4. 让它列出项目，确认能读到公司存储桶：发送"列一下桶里有哪些项目"。
5. 从"下载"文件夹删除配置包。
:::

::: utterances
- 导入这个配置包
- 导入配置包 /Users/zhang/Downloads/某某咨询.zip
- 先帮我检查一下这个配置包，不要写入
- 列一下桶里有哪些项目
:::

**拖不进去或它说找不到文件**：直接把配置包的完整路径发给它（上面第二句）。导入工具只接受完整路径。复制路径：Mac 在访达里选中文件，按 `kbd:Option+Command+C`；Windows 11 右键文件 →"复制文件地址"，Windows 10 按住 Shift 右键 →"复制为路径"。

**只检查、不写入**：说"先帮我检查一下这个配置包，不要写入"，它会以只校验模式运行，结果为"配置包校验通过（未写入）：…"。适合在正式导入前确认文件没问题。

### 带 SSH 与 ve 配置的配置包

如果配置包里有 SSH 主机或 ve 配置名，结果里还会多出下面这样的行（示例）：

```text
SSH 主机 zt-prod 已写入 /Users/zhang/.ssh/config 的受管块（私钥文件仅本人可读）。
火山引擎 ve profile 名「zt-ak」已写入 zt-volc 设置 /Users/zhang/.dsh/zhitong/volc.config.json；配置包不含 ve 的密钥，请用户在自己的终端运行 ve configure set --profile zt-ak 建立该 profile。
```

第二行要求的操作见本页[火山引擎 ve 配置](/docs/config-package/#火山引擎-ve-配置仅运维人员)。

## 导入时检查什么

导入工具先完整检查，**有任何一项不符合就整体拒绝，不会只导入一部分**。报错只给出字段位置和规则，不会显示任何密钥的值。

| 检查项 | 规则 |
|---|---|
| 文件大小 | 配置包文件和其中的 `zhitong.config.json` 都不超过 1 MiB |
| zip 结构 | zip 里恰好有一个 `zhitong.config.json`，放在根目录或往下一层；Mac 压缩时产生的 `__MACOSX/` 副本和其它文件忽略 |
| 格式标记 | `format` 必须是 `zhitong.config/1` |
| 公司名 | 不能为空 |
| 存储桶地址 | 只写主机名（可带端口），不带 `https://` 和路径 |
| 区域 | 不能为空 |
| 桶名 | 只含小写字母、数字和 `-`，长度 3–63 |
| 目录前缀 | 可以为空（表示桶根）；首尾的 `/` 会去掉；不能含 `.`、`..` 段、反斜杠和控制字符 |
| 访问密钥 | 两项都不能为空；首尾空白会去掉 |
| SSH 主机 | 别名只含字母、数字、`_`、`-` 且不重复；地址只能是主机名或 IP；用户只含字母、数字、`.`、`_`、`-`；端口 1–65535，默认 22 |
| ve 配置 | 出现时必须有配置名 |
| 多余字段 | 出现上面以外的字段一律拒绝，避免字段名拼错后设置悄悄不生效 |

## 导入后写到哪里

| 内容 | 写到 | 说明 |
|---|---|---|
| 存储桶密钥 | 本机凭据存储 `~/.dsh/.credentials.yaml`（Windows `%USERPROFILE%\.dsh\.credentials.yaml`） | 仅当前用户可读 |
| 存储桶地址、区域、桶名、前缀 | 桌面版配置 `~/.dsh/profiles/desktop/cordis.patch.yml` | 保存后文件工具立即按新设置重新加载，不需要重启 |
| 公司名 | 不保存 | 只在导入结果里显示 |
| ve 配置名、区域，SSH 主机别名 | `~/.dsh/zhitong/volc.config.json` | 只有名字，没有地址和密钥；仅当前用户可读 |
| SSH 主机地址、端口、用户 | `~/.ssh/config`（Windows `%USERPROFILE%\.ssh\config`）**开头**的受管块 | 块首尾各有一行 `# >>> zhitong config-import` 与 `# <<< zhitong config-import <<<` 标记；块外内容不动 |
| SSH 私钥 | `~/.ssh/zhitong/<别名>` | 仅本人可读 |

## 密钥不会出现在哪里

- 导入结果、报错信息、上表中的配置文件里都**不出现密钥的值**。
- 它被要求不向您复述任何密钥；之后的文件操作每次从凭据存储读取密钥，密钥不进入对话。
- 请不要把密钥粘贴进对话框：您输入的文字会作为对话内容发送给模型服务。界面会遮住看起来像密钥的文字，但这只是显示上的遮盖。
- 设置页里的密钥是只写的：保存后页面不再显示明文。

更多见[数据与安全](/docs/security/)。

## 出错时怎么办

报错原文出现在工具结果里。下表左列是报错原文（`{}` 处为具体内容）。

| 报错 | 原因 | 处理 |
|---|---|---|
| 找不到配置包 {路径} | 路径写错，或文件已被移动 | 重新复制完整路径发给它 |
| path 必须是配置包的本机绝对路径 | 只给了文件名或相对路径 | 发完整路径（以 `/Users/` 或 `C:\` 开头） |
| 配置包 {N} 字节，超过上限 1048576 字节 | 选错了文件，或 zip 里夹带了大文件 | 确认选的是服务方给的配置包；仍报错请服务方重发 |
| {文件} 不是有效的 zip 文件 | 下载不完整或文件损坏 | 重新从服务方获取 |
| zip 里没有 zhitong.config.json | zip 里没有这个文件，或放得太深（超过一层目录） | 请服务方按要求重新打包 |
| zip 里有多个 zhitong.config.json | zip 里放了不止一份 | 请服务方重新打包 |
| zhitong.config.json 不是合法 JSON（位置 {N} 附近） | 文件被手工改坏 | 请服务方重发；报错只给位置，不含内容 |
| 配置包校验失败：- {字段} … | 一项或多项不符合上节规则，每行一项 | 把这段报错转给服务方。报错里只有字段名，不含密钥，可以直接转发 |
| 当前 profile 里没有 id 为 zhitong-tool-tos 的 TOS 插件条目；请确认已启用智通数工AI bundle | 本机配置不是智通数工AI 的，常见于以前装过 DeepSeek Harness 桌面版 | 按[安装](/docs/install/#应用名与数据位置)中"以前装过 DeepSeek Harness 桌面版"的方法重建配置，再导入 |
| 当前 profile 没有凭据存储，无法保存密钥 / 当前 profile 不支持保存插件配置… | 同上，本机配置不完整 | 同上；仍不行请联系服务方 |
| TOS 访问密钥已存入凭据存储，但 TOS 设置未能写入 profile：{原因} | 密钥已保存，连接设置没写进去 | 再导入一次；仍失败把整段报错发给服务方 |
| TOS 设置已导入，但 ssh / volc 段未能写入：{原因} | 存储桶已经可以用，SSH 或 ve 部分失败 | 按{原因}处理后重新导入；常见原因见下一行 |
| OpenSSH 配置里只有受管块的开头标记，没有结尾标记… | `~/.ssh/config` 里的受管块被手工改坏 | 用文本编辑器打开 `~/.ssh/config`，删掉 `# >>> zhitong config-import` 开头的那段残留，再重新导入 |

导入成功之后，文件工具如果报"TOS 尚未配置（缺少 …）"或"凭据存储里没有 TOS 访问密钥"，说明这台电脑上的配置或密钥丢失了（例如重建了配置、删除了凭据），重新导入一次即可。访问桶时被拒绝，见[常见问题与排错](/docs/troubleshooting/#配置包与存储桶)。

## 重新导入与更换

| 情况 | 做法 | 结果 |
|---|---|---|
| 密钥轮换 | 服务方发新配置包，按导入步骤再导入一次 | 两项密钥被新值覆盖，下一次文件操作即用新密钥 |
| 更换桶或前缀 | 同上 | 连接设置整体替换为新值 |
| SSH 主机变化 | 同上 | `~/.ssh/config` 里的受管块整块替换，块外内容不动 |
| 撤销本机密钥 | 在设置页的凭据管理里删除 `ZT_TOS_ACCESS_KEY_ID`、`ZT_TOS_SECRET_ACCESS_KEY`，或编辑 `~/.dsh/.credentials.yaml` 删除这两项 | 文件工具不再能访问桶，提示重新导入 |

一台电脑同一时间只连接一个公司存储桶。本机缓存目录 `~/zhitong` 不区分公司；切换到另一家公司的配置包之前，先让它确认没有本机改过但没推回桶的文件。

## 火山引擎 ve 配置（仅运维人员）

只有要用[火山引擎运维](/docs/features/cloud/)能力的人员需要做这一步。`ve` 是火山引擎官方命令行工具，它的密钥保存在 `ve` 自己的配置里，**不经过配置包，也不经过对话**。

::: steps
1. 在自己的终端里安装 `ve`（或按火山引擎文档的其它方式安装）：

   ```bash
   npm i -g @volcengine/cli
   ```

2. 建立配置。`--profile` 的名字必须与配置包里的 ve 配置名一致（导入结果里会写出，如 `zt-ak`）；AK/SK 用火山引擎控制台为您本人创建的子账号密钥：

   ```bash
   ve configure set --profile zt-ak --region cn-beijing --access-key <AK> --secret-key <SK>
   ```

3. 验证：

   ```bash
   ve --profile zt-ak sts GetCallerIdentity
   ```

   也可以在对话里让它运行火山引擎运维的身份检查。
:::

::: note 不要让它代办这一步
不要把 AK/SK 写进配置包、贴进对话，也不要让它执行 `ve configure set`。具体参数名以您所装 `ve` 版本的 `ve configure set --help` 为准。子账号权限只给 ECS 只读与启停、安全组和 TOS 只读需要的策略。
:::
