## 一句话

由计价表算单方造价、各章占比与造价驱动项，可与案例索引里的同类项目对标；金额由脚本计算，需您复核。

## 适用场景

- 结算、预算、招标控制价完成后，要出一组单方造价和章节占比指标。
- 归档前，要把本项目的关键指标写进案例索引。
- 想知道本项目的单方和公司历史同类项目相比是高是低。
- 想看哪几条清单项是造价的主要构成（造价驱动项）。

## 您可以这样说

::: utterances
- 算一下 2026-007 的单方造价和各章占比。
- 用审定计价表算指标，面积按项目说明里的 18,600 平方米。
- 找两个公司做过的办公楼，和本项目的单方对标一下。
- 6 号楼和 7 号楼两份计价表一起算，总建筑面积 12,000 平方米。
- 我这里有含税总造价，按它算单方。
- 造价最高的前 10 条清单项是哪些？
:::

## 需要准备的资料

| 资料 | 要求 |
|---|---|
| 计价表 | `.xlsx` / `.xlsm` 的分部分项计价表：控制价、预算、结算均可；多个单体可以一起给。指标按合同价口径取数 |
| 总建筑面积 | 只用项目说明或资料里写明的数，并记下出处，例如「项目说明」「设计说明第 3 页」。找不到时助手会问您，不会估 |
| 含税总造价（可选） | 您给出时，单方按它计算；不给时，脚本按「费用表合计 → 清单明细合计」的顺序取 |
| 对标数据（可选） | 来自桶根目录的 `案例索引.md`，由 [归档](/docs/features/archive/) 维护 |

::: note
国标编码行不到一半的表（例如万元估算表、审核汇总表）不参与指标计算，并以 `sheets_skipped_non_list`（info）说明。
:::

## 它会怎么做

::: steps
1. **读项目说明**（`read 项目说明.md`）。找关键文件指引里的计价表，以及总建筑面积、业态、结构。
2. **计价表不明确时先预检**（`probe.py probe`，与 [送审审定核对](/docs/features/check/) 共用），把候选列给您，用选项卡请您确认。
3. **确定面积来源**。面积写进命令时同时记下来源（`--area-source`）。
4. **（可选）准备对标**。助手读 `案例索引.md`，挑业态相同或相近的项目，把每一行原样抄出的字段写成 `对标.json`。案例索引里没写的数不填，也不换算口径。
5. **运行指标计算**（`indicator.py run`），工作目录 `工作/<日期>-指标/`。
6. **汇报**：总造价或清单明细合计与口径 → 单方（值、面积、面积来源）→ 占比最高的几章与造价驱动项 → 费用构成 → 对标偏差与样本数 → 未计入文件与告警。
7. **写待确认清单并推回桶**（`tos_push`）。
:::

### 示例：2026-007 某综合办公楼（示例数据）

您说："用审定计价表算指标，再找两个办公楼对标。"

**第 1 步：读项目说明。** 建筑面积 18,600.00 m²（地上 15,200.00、地下 3,400.00），业态办公，结构框架-剪力墙。审定计价表在 `资料/4 结算资料/审定计价表.xlsx`。

**第 2 步：查案例索引。** 助手读 `案例索引.md`，找到两行办公项目：

| 编号 | 工程名 | 业态 | 规模 | 咨询类型 | 关键指标 |
|---|---|---|---|---|---|
| 2025-018 | 某科创中心一期 | 办公 | 21,300 m² | 结算审核 | 审定单方 1,688.40 元/m²（清单明细合计口径） |
| 2024-033 | 某政务服务中心 | 办公 | 14,750 m² | 结算审核 | 审定单方 1,571.20 元/m²（清单明细合计口径） |

写成 `工作/2026-10-20-指标/对标.json`：

```json
{"building_type": "办公", "structure": "框架-剪力墙", "project_id": "2026-007",
 "peer_library": [
   {"project_id": "2025-018", "name": "某科创中心一期", "building_type": "办公",
    "structure": "框架-剪力墙", "gross_area": 21300, "unit_cost": 1688.40},
   {"project_id": "2024-033", "name": "某政务服务中心", "building_type": "办公",
    "structure": "框架", "gross_area": 14750, "unit_cost": 1571.20}]}
```

**第 3 步：运行。**

```text
indicator.py run --files "资料/4 结算资料/审定计价表.xlsx" \
  --gross-area 18600 --area-source 项目说明 \
  --baseline 工作/2026-10-20-指标/对标.json --out 工作/2026-10-20-指标/
```

**第 4 步：助手的汇报（节选）。**

> 清单明细合计 29,623,713.84 元。这是清单明细合计，不是总造价：审定计价表里没有费用表，没有算进措施费里没读入的部分、其他项目费、规费、税金。
>
> 按清单明细合计算的单方 1,592.67 元/m²，面积 18,600.00 m²，来源：项目说明。
>
> 占比最高的三章：混凝土及钢筋混凝土工程 61.49%（单方 979.34 元/m²）、措施项目 13.47%、门窗工程 9.95%。造价驱动项前三：现浇构件钢筋 5,781,091.26 元（19.52%）、金属（塑钢、断桥）窗 1,613,660.15 元（5.45%）、有梁板 1,465,951.96 元（4.95%）。
>
> 费用构成：没有单位工程费用表，不显示构成。
>
> 同类对标：同类均值 1,629.80 元/m²（2 个项目），本项目偏差 −2.28%。
>
> 状态：完成（ok）。告警：`fee_total_unavailable`（info）、`sheets_skipped_by_title`（info）。以上金额、单方、占比均为脚本取数，需人工复核。

## 得到什么

`工作/2026-10-20-指标/` 下：

::: filetree
```text

    2026-10-20-指标/
      result.json        # 脚本完整结果
      指标结果.xlsx      # 工作底稿
```

|---|---|

## 结果怎么读

### 总造价口径（`cost_basis`）

| 口径 | 含义 | 汇报时 |
|---|---|---|
| `user_input` 用户录入 | 您给了含税总造价 | 单方按您给的数算 |
| `fee_table` 取自费用表 | 每份文件都取到了费用表合计，并与各单位工程费用表勾稽过 | 可称为总造价 |
| `itemized` 清单明细合计 | 没有可采用的费用表合计 | 必须说「这是清单明细合计，不是总造价」，并说明没算进哪些部分（`cost_basis_missing`） |

回落到清单明细合计时，指标行名会改成「清单明细合计(元,不是总造价;…)」「按清单明细合计算的单方(元/㎡,不是单方造价指标;…)」，不会再叫「总造价」「单方造价」。

### 单方与各章单方

- 单方 = 总造价（或清单明细合计）÷ 总建筑面积。没有面积时单方为空，说明栏写「未提供总建筑面积」，并给出 `area_missing`（warn）。
- 各章单方分别四舍五入到分，相加可能与总单方差 0.01。

### 对标

- 对标值是同类项目单方的平均数，`avg_sample_count` 是参与平均的项目数。
- 偏差 =（本项目单方 − 同类均值）÷ 同类均值；正数偏高，负数偏低。
- 本项目一侧用清单明细合计口径的单方；同类项目一侧用案例索引里抄来的数。两边口径不同，偏差就没有意义，所以案例索引里的指标要写明口径。
- 匹配同类项目时，业态相同、结构相同、面积相近的排在前面，最多取 5 个。

### 费用构成

只有工作簿里有单位工程费用表，且分部分项、技术措施、组织措施、其他项目、规费、增值税六项相加与费用表合计相差不超过 1 元时才显示。不显示时，助手转述原因，不会自己拆分。

## 需要您确认的事项

::: confirm
所有金额、单方、占比都是脚本取数结果，需要人工复核。

1. **面积和出处**。助手只用写明的面积，并在汇报里注明来源。资料里多处面积不一致时，请您指定用哪一个。
2. **口径回落**。出现 `itemized` 时，确认是否要补一个含税总造价，或改用带费用表的计价表。
3. **未计入的文件和表**。看「未计入文件」工作表和 `files_failed`；error 级告警逐条确认。
4. **对标样本**。确认案例索引里挑出的项目确实可比，样本数是否够用。
5. **疑似重复清单**。多份文件一起算时若出现 `file_overlap_suspect`，请确认没有把同一份清单选了两次（同构楼栋确实可能是同一份清单，脚本不会自动剔除）。
:::

## 限制与注意

- **只读 `.xlsx` / `.xlsm`**，`.xls` 需另存。读不出的版式会进入「未计入文件」。
- **不估面积**：没有写明的面积不会被推算。
- **分单体指标**：多份单体文件一起算时，脚本给出的是合计口径的单方与占比，不按面积占比给每个单体分摊。
- **对标依赖案例索引**：案例索引是公司自己归档的数据，没有行业数据库。案例索引里缺数的项目不参与对标。
- **告警提示里的旧界面说法**：「指标计算」对话框里的总建筑面积，对应您在对话里给出的面积；「含税总造价」对应您给出的总造价。直接在对话里告诉助手即可。
- **模型不算钱**：助手不手算单方、占比和偏差，脚本没给的数会说没有。

## 常见问题

### 为什么结果写「清单明细合计」，不写「总造价」？

所选计价表里没有可采用的费用表合计，脚本只能把清单行加起来。这个数不含其他项目费、规费、税金，不是总造价。您可以告诉助手含税总造价，或换用带费用表的计价表。

### 送审表能算指标吗？

能。指标计算不区分送审、审定。以示例项目为例，用送审计价表算出的按清单明细合计算的单方是 1,641.42 元/m²，用审定计价表算出的是 1,592.67 元/m²。

### 面积我记得大概是 1.8 万平方米，能直接用吗？

助手只用项目说明或资料里写明的面积，并记录出处。您口头给出的面积也可以用，来源会记为您提供；建议给出准确值。

### 对标偏差 −2.28% 说明本项目造价偏低吗？

只说明本项目的单方比所选同类项目的平均数低 2.28%。样本只有 2 个，项目规模、结构、标准都不完全相同，是否合理要由您判断。

### 费用构成为什么不显示？

费用构成要求有单位工程费用表，且六项相加与费用表合计相差不超过 1 元。没有费用表、或勾稽不过时不显示，助手会转述原因。

### 指标会自动写进案例索引吗？

不会在计算时写。归档时由 [归档](/docs/features/archive/) 把关键指标写进本项目在案例索引里的那一行。
