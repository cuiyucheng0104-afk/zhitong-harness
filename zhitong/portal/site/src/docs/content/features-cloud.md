## 一句话

供公司管理员用 ve 命令行和 SSH 查看、操作火山引擎资源；会中断服务或改变访问范围的操作须您确认后执行。

## 适用场景

- 公司管理员查看服务器：ECS 实例是否在运行、内外网 IP、绑定了哪些安全组。
- 管理员换了网络（在家、出差）：把本机当前的出口公网 IP 同步进安全组白名单，再 SSH 登录。
- 管理员排查服务器问题：登录后查看磁盘、进程、容器状态和日志。
- 维护窗口：启动、停止或重启 ECS 实例。
- 多人协作出现文件覆盖时：只读确认公司的火山引擎对象存储（TOS，下文称"公司存储桶"）是否开启了版本控制。

::: note
本能力面向负责公司云资源的管理员。普通造价工程师存取项目文件不需要它，项目文件的读写由公司存储桶的文件工具完成。
:::

## 您可以这样说

::: utterances
- 看一下 zt-prod 那台服务器现在什么状态。
- 我换了网络，把我现在的 IP 加进 zt-prod 的 SSH 白名单，标记用 alice。
- 登录 zt-prod，看一下磁盘还剩多少，再看最近 200 行 nginx 错误日志。
- 公司存储桶的版本控制开着吗？
- 今晚维护，把 zt-prod 停掉。
- 把 zt-batch 开起来。
:::

以上实例名、安全组名、标记均为示例。

## 需要准备的资料

本能力用到配置包里的可选部分。配置包是服务方按贵司环境整理的压缩文件，含公司存储桶的地址、桶名、目录前缀、访问密钥和公司名；需要运维时，还可含 SSH 主机和 ve 配置名。格式见[导入配置包](/docs/config-package/)。

| 资料 | 放在哪里 | 格式要求 | 必需或可选 |
|---|---|---|---|
| 配置包里的火山引擎段 | 导入后写进本机 `~/.dsh/zhitong/volc.config.json` | ve 配置名（profile）和区域，只有名称，不含密钥 | 必需 |
| 配置包里的 SSH 主机 | 导入后写进 `~/.ssh/config` 开头的受管块，私钥在 `~/.ssh/zhitong/<别名>` | 别名、主机、端口、用户；私钥可选 | SSH 登录时必需 |
| ve 命令行工具 | 本机 | 火山引擎官方 CLI，需另行安装 | 必需 |
| ve 的访问密钥 | ve 自己的配置里 | 管理员在自己的终端里设置一次；名称须与配置包里的 ve 配置名一致 | 必需 |
| OpenSSH 客户端 | 本机 | `ssh` 命令可用 | SSH 登录时必需 |
| 当前出口公网 IP | 您告诉它，或由它访问一个返回纯文本 IP 的网址取得 | 必须是公网地址；内网、回环地址会被拒绝 | 同步白名单时必需 |

ve 的安装与设置由管理员在自己的终端里完成，不经过对话：

```bash
npm i -g @volcengine/cli
ve configure set --profile zt-ak --region cn-beijing --access-key <AK> --secret-key <SK>
ve --profile zt-ak sts GetCallerIdentity
```

`zt-ak`、`cn-beijing` 是示例，`--profile` 的值要与配置包里的 ve 配置名一致；具体参数名以所装版本的 `ve configure set --help` 为准。AK/SK 请用火山引擎控制台为您本人创建的子账号密钥，权限只给 ECS 查看与启停、安全组、TOS 只读所需的策略。

::: note
不要把 AK/SK 写进配置包、贴进对话，也不要让它代您执行 `ve configure set`。它只读取配置名和主机别名，不读取也不回显任何密钥。
:::

## 它会怎么做

### 查看类操作

::: steps
1. 验证身份 `volc.py whoami`：确认 ve 配置可用。
2. 查看实例 `volc.py ecs-list`、`volc.py ecs-status`：列实例，或查看某台的状态、IP 和绑定的安全组。
3. 查看安全组 `volc.py sg-show`：列出入方向规则。
4. 查看存储桶 `volc.py tos-buckets`、`tos-stat`、`tos-ls`、`tos-versioning`、`tos-lifecycle`：只读。
5. SSH 只读命令 `volc.py ssh-exec`：先列出可用别名 `ssh-hosts`，不在列表里的别名一律拒绝。
:::

这些操作直接执行，不需要确认。

### 改动类操作：先预演，再确认，再执行

::: steps
1. 预演 `--dry-run`：只输出将执行的命令和影响，不调用任何写接口。
2. 确认提问 `ask_user_question`：写清对象（实例名与 ID、安全组名与 ID、主机别名）、动作、影响（谁会失去访问、哪些服务会中断）和原命令。选项只有"执行"和"不执行"。
3. 只有您选"执行"，它才在原命令上加 `--yes` 重跑，参数一个字不改。
4. 一次确认只对应一条命令；第二条命令重新问。
5. 您没有回答、选了其他选项或要求修改时，不执行；改了参数就回到第 1 步。
:::

它不会在第一次调用时就带 `--yes`，不会用 `--yes` 去"试试"，也不会替您确认。向全网段 `0.0.0.0/0` 开放的规则默认被拒绝，只有您亲口要求全网开放时才会加 `--allow-world`，并在确认问题里点明风险。

| 操作 | 子命令 | 需要您确认 |
|---|---|---|
| 验证身份 | `whoami` | 否 |
| 列实例、查状态 | `ecs-list`、`ecs-status` | 否 |
| 启动 ECS | `ecs-start` | 否 |
| 停止 ECS | `ecs-stop` | 是 |
| 重启 ECS | `ecs-reboot` | 是 |
| 查看安全组规则 | `sg-show` | 否 |
| 增加、删除入方向规则 | `sg-authorize`、`sg-revoke` | 是 |
| 同步本机 IP 进白名单 | `sg-sync-ip` | 有变更时是 |
| 查看存储桶、生命周期、版本控制 | `tos-buckets`、`tos-stat`、`tos-ls`、`tos-lifecycle`、`tos-versioning` | 否 |
| 列 SSH 主机 | `ssh-hosts` | 否 |
| SSH 执行只读命令 | `ssh-exec` | 否 |
| SSH 执行其他命令 | `ssh-exec` | 是 |

只读命令包括：`ls`、`cat`、`head`、`tail`、`wc`、`grep`、`sort`、`cut`、`tr`、`df`、`du`、`free`、`uptime`、`ps`、`pgrep`、`whoami`、`id`、`date`、`uname`、`pwd`、`stat`、`ss`、`nproc`、`lsblk`、`journalctl`、`echo`，以及 `docker ps / logs / images / stats / version / info`、`systemctl status / is-active / is-enabled / list-units / list-unit-files`。用管道连接时每一段都要在名单内；含重定向、命令替换、后台符，或带写入类选项时，按需要确认处理。

### 示例：在外放行本机 IP 并查看服务器（示例数据）

以下对话与结果均为示例数据，IP 地址以占位符表示。2026-10-20，管理员在家里说："我换了网络，把我现在的 IP 加进 zt-prod 的 SSH 白名单，标记用 alice，然后看看服务器磁盘。"

::: steps
1. 验证身份 `volc.py whoami`：完成，ve 配置 `zt-ak`，区域 `cn-beijing`。
2. 查看实例 `volc.py ecs-status`：zt-prod（i-yeaaaaaaaa01）运行中，绑定安全组 zt-prod-sg（sg-aaaaaaaa01）。
3. 它问您当前的出口公网 IP，您告诉它。
4. 预演 `volc.py sg-sync-ip --dry-run`，计划为：

   ```text
   安全组 sg-aaaaaaaa01（zt-prod-sg）：放行 <新 IP>/32 的 tcp 端口 [22]，
   并撤销本标记下的旧来源 ['<旧 IP>/32']
   规则描述：zt-ssh-sync:alice
   ```

5. 确认提问：对象是安全组 zt-prod-sg（sg-aaaaaaaa01）；动作是放行新 IP 的 22 端口、撤销标记 alice 下的旧 IP；影响是旧 IP 不能再 SSH 登录，其他同事各自标记的规则不受影响；附原命令。您选"执行"。
6. 原命令加 `--yes` 重跑：先放行新 IP，成功后再撤销旧 IP。结果为完成。
7. 列主机 `volc.py ssh-hosts`，执行只读命令 `volc.py ssh-exec --host zt-prod --command "df -h"`，不需要确认。它转述各分区的使用率。
:::

随后您说"今晚维护，把 zt-prod 停掉"。它先预演 `ecs-stop --dry-run`，再向您确认；如果跳过确认直接执行，脚本会以"该操作需要确认：stop 实例 i-yeaaaaaaaa01（zt-prod，当前 RUNNING）会中断该机器上的服务"结束，不会停机。

### 示例：确认 2026-007 被覆盖的文件能否找回（示例数据）

以下为示例数据。同事归档 2026-007 时，推送 `工作/2026-10-19-核对/待确认清单.md` 提示"拉取后别人改过"，同事选择了覆盖。审核负责人想知道被覆盖的版本还在不在，管理员问："公司存储桶的版本控制开着吗？"

::: steps
1. 列桶 `volc.py tos-buckets`，确认要查的桶（桶名不在页面展示）。
2. 查看版本控制 `volc.py tos-versioning`：只读。它原样转述输出，示例中显示版本控制已开启，同时带一条"命令写法未核实"的提示（`tosutil_syntax_unverified`），建议到 TOS 控制台再确认一次。
3. 它说明：版本控制开启时，覆盖不会丢失旧版本；找回旧版本请在火山引擎控制台按对象路径（公司前缀之下）`项目/2026-007-某综合办公楼/工作/2026-10-19-核对/待确认清单.md` 查看历史版本并恢复。本能力不提供回退操作。
:::

## 得到什么

运维操作的结果显示在对话里，不写入任何项目目录。导入配置包时在本机写入的设置，以及您要求留痕时的记录如下：

::: filetree
```text
~/.dsh/zhitong/volc.config.json              # ve 配置名、区域、SSH 别名；只有名称，不含密钥
~/.ssh/config                                # 开头的受管块：主机、端口、用户
~/.ssh/zhitong/zt-prod                       # SSH 私钥，权限仅本人可读
知识库/公司经验/运维记录-2026-10-20.md        # 仅在您要求留痕时写入公司存储桶
```
:::

| 文件 | 说明 |
|---|---|
| `volc.config.json` | 导入配置包时写入，默认在 `~/.dsh/zhitong/`；重新导入配置包会更新 |
| `~/.ssh/config` 受管块 | 首尾各有一行 `zhitong config-import` 标记，重新导入时整块替换，块外内容不动；Windows 在 `%USERPROFILE%\.ssh\config` |
| `~/.ssh/zhitong/<别名>` | 配置包里带私钥时才有 |
| 运维记录 | 按[企业知识库](/docs/features/knowledge/)的规则写：只写已发生的事实，带日期，不含密钥和私钥 |

## 结果怎么读

通用含义见[结果状态与告警](/docs/results/)。本能力的读法：

| 结果 | 含义 | 您要做什么 |
|---|---|---|
| 完成（`ok`） | 操作完成 | 看转述的结果 |
| 完成，且 `changed: false` | 什么都没改：已在目标状态、规则已存在或已同步 | 无需操作；它不会说成"已执行" |
| 部分完成（`partial`） | 列表被截断、等待超时，或旧规则未撤销 | 看它说明缺了什么 |
| 部分完成 + `stale_rule_revoke_failed` | 新 IP 已放行，旧 IP 仍有访问权限 | 复核安全组规则 |
| `--wait` 等待超时 | 请求已发出，结果未确认 | 用 `ecs-status` 复查，不要重发 |
| 失败 `confirmation_required` | 改动类操作没有确认 | 按确认流程处理 |
| 失败 `ve_timeout`、`ssh_timeout` | 写操作的实际结果未知 | 先用查看类操作确认现状，再决定是否重试 |
| 失败 `ssh_connect_failed` | SSH 连不上 | 先怀疑白名单过期，重新同步本机 IP |
| 失败 `volc_profile_missing` | 找不到 ve 配置名 | 检查配置包是否含火山引擎段，或重新导入 |
| 失败 `ve_not_found` | 本机没有 ve | 安装官方 CLI |
| 失败 `ip_not_public`、`world_open_refused` | IP 不是公网地址；拒绝向全网段开放 | 给出正确的出口公网 IP |
| `ssh-exec` 的 `exit_code` 非零 | 远端命令执行失败，连接本身正常 | 看输出；输出被截断时缩小范围 |

## 需要您确认的事项

::: confirm
- 每一条停止、重启 ECS 的命令，以及它对业务的影响。
- 每一次增删安全组规则、同步白名单：谁会获得或失去访问。
- 每一条 SSH 非只读命令：命令以登录账号的权限在远端运行。
- 任何向全网段开放的请求。
- 超时后的实际结果：先查看现状，再决定是否重试。
- 首次使用时的输出：脚本按火山引擎官方文档和 SDK 字段编写，测试用的是按字段手写的样例，尚未与真实 ve、tosutil 的输出逐项核对。首次在贵司环境使用时，请对照火山引擎控制台核对结果。
:::

## 限制与注意

- 本能力只供公司管理员使用。每位使用者在自己的电脑上单独设置 ve 的访问密钥，建议用最小权限的子账号。
- 不提供：删除桶或对象、修改桶的生命周期与版本控制、创建或删除 ECS 实例、修改安全组以外的 VPC 资源、`ve configure`。这些请在火山引擎控制台完成。公司存储桶是公司唯一的资料真源，桶内文件的旧版本回退也在控制台操作。
- 存储桶相关的子命令都是只读的。项目文件的存取用文件工具 `tos_ls`、`tos_pull`、`tos_push`，不经过本能力。
- 只读命令名单是为了少问一次确认，不是安全隔离：命令仍以登录账号的权限在远端运行。
- 不支持持续跟随输出（`tail -f`、`journalctl -f`、`docker logs -f`），请改用 `tail -n` 取最近若干行。
- 查看生命周期与版本控制时，结果会带"命令写法未核实"的提示（`tosutil_syntax_unverified`）；tosutil 的输出认不出时报 `tosutil_output_unrecognized`，不会当作"没有桶"。需要时请在 TOS 控制台确认。
- 同一安全组多人共用时，各自用自己的标记同步 IP；同步只撤销本标记下的旧 IP，不动别人的规则。
- 它不会把配置文件内容、密钥、私钥贴进对话；日志里出现形似密钥的内容也不转述。
- ve 首次调用 tosutil 时会自动安装它。

## 常见问题

### 普通造价工程师需要用这个能力吗？

不需要。开项目、读资料、核对、归档用的是公司存储桶的文件工具，配好配置包即可。本能力只给负责服务器和安全组的管理员使用，而且要另装 ve 并设置访问密钥。

### 为什么不能把 AK/SK 直接发给它代为设置？

对话内容会作为上下文发给模型服务，密钥不应出现在对话里。ve 的密钥只保存在 ve 自己的配置中，由您本人在终端里设置；它只读取配置名，不接触密钥。

### 它说"该操作需要确认"，我该怎么做？

这是保护机制：改动类操作没有您的确认就不会执行。它会先预演，把对象、动作、影响和原命令列在确认问题里，您选"执行"后才真正执行。

### 白名单同步后还是连不上？

先确认您给的 IP 是当前的出口公网 IP（换网络后会变）；再用 `sg-show` 看规则是否已生效；如果结果是部分完成且提示旧规则未撤销，新 IP 其实已放行，问题可能在服务器端。连接失败的提示会附上 ssh 的错误信息，可据此判断。

### 能用它回退存储桶里某个文件的旧版本吗？

不能。它只能只读查看版本控制是否开启，回退旧版本、修改版本控制请在火山引擎控制台操作。

### 命令超时了，要不要再执行一次？

先不要。超时表示请求可能已经执行，结果未知。让它用查看类操作（如 `ecs-status`、`sg-show`）确认现状，再决定是否重试。
