# 06 文档子站

本章规定 `/docs/` 文档子站：信息架构、URL、内容源与构建、页面布局、Markdown 扩展语法、能力页模板、组件、站内搜索、动效、图片、无障碍、性能与验收。正文在 [文档内容/](文档内容/)，本章只规定它们怎样被写、被编译、被展示。设计变量、交互基础件、示例项目与验收方式沿用 [00 章](00-总览与设计系统.md)；顶栏与全局按钮见 01 章。

## 2. URL 与链接规则

1. 所有文档页的 URL 形如 `/docs/<slug>/`：小写 ASCII、数字、`-`，能力页多一级 `features/`。必须带尾斜杠，因为部署件按目录取 `index.html`（00 章 §3.1）。
2. `/docs` 与 `/docs/install`（无尾斜杠）由 nginx 的 `try_files $uri $uri/` 自动 301 到带斜杠的地址，前端不另做跳转。
3. 不存在的 `/docs/...` 返回 HTTP 404 与 404 页（§3.7）。前端路由对未知路径同样渲染 404 页，不跳转首页。
4. 页内锚点 id 由标题文字生成：去掉首尾空白，删除除字母、数字（含中文）、`-`、空格之外的字符，空格换成 `-`，英文转小写；同页重名依次加 `-2`、`-3`。例：「校验安装包」→ `#校验安装包`，「Windows：SmartScreen 拦截」→ `#windowssmartscreen-拦截`。锚点 id 只由这一个函数生成（§3.4 的清单与正文渲染共用），构建期比对二者一致。
5. 正文里的站内链接一律写绝对路径：`/docs/<slug>/`、`/docs/<slug>/#<锚点>`、首页章节 `/#faq`。构建期检查每个站内链接：路径在路由表里，锚点在目标页存在；不通过则构建失败。
6. 外部链接在新标签打开（`target="_blank" rel="noopener noreferrer"`），链接后显示 12px 外链图标，`aria-label` 末尾加「（在新标签页打开）」。正文尽量不放外链：产品文档里的外部地址（如 `https://api.deepseek.com`）写成代码，不写成链接。
7. 站内链接在前端由 `RouterLink` 接管，不整页刷新；锚点跳转按 §9.3。

### 3.2 frontmatter

每个正文文件以 YAML frontmatter 开头。字段固定，出现未列字段或缺必填字段时构建失败。

| 字段 | 必填 | 规则 |
|---|---|---|
| `title` | 是 | 与 §1.1「标题」逐字一致；用作 H1、`<title>`、侧栏文字（文档首页例外：侧栏写「文档首页」，H1 固定为「文档」，见 §4.4） |
| `slug` | 是 | 与 §1.1 URL 中 `/docs/` 之后、尾斜杠之前的部分一致；首页写 `index` |
| `group` | 是 | §1.2 的组名之一；首页写 `首页` |
| `order` | 是 | 组内序，从 1 起，组内不重复；首页 0 |
| `summary` | 是 | ≤ 60 字；用于文档首页卡片、搜索结果、`<meta name="description">`、页面 H1 下的导语 |
| `updated` | 是 | `YYYY-MM-DD`；显示为「更新于 …」，写入 sitemap 的 `lastmod` |
| `sources` | 是 | 至少一条仓库相对路径（如 `zhitong/skills/zt-reconcile/SKILL.md`）；构建期检查路径存在；不在页面上显示 |
| `layout` | 否 | 只有首页写 `home` |

`sources` 不对访客展示：仓库路径对造价工程师没有意义，它的用途是让维护者知道改了哪份源文件就要复核哪页文档。构建期在仓库内运行，可直接检查路径存在。

### 3.3 Markdown 编译：选型与理由

**选定**：构建期编译，`unplugin-vue-markdown` 把每个 `.md` 编译成一个 Vue 单文件组件，Markdown 引擎为 `markdown-it` 14.x，插件：

| 用途 | 包 | 说明 |
|---|---|---|
| 容器 | `markdown-it-container` 4.x | §5 的 `note / tip / confirm / steps / filetree / utterances / doc-cards / release-current` |
| 标题锚点 | `markdown-it-anchor` 9.x | `slugify` 用 `build/docs-slug.ts`；`permalink` 关闭，锚点链接由 `HeadingAnchor` 渲染 |
| 代码高亮 | `shiki` 3.x + `@shikijs/markdown-it` 3.x | 构建期高亮，只加载 `bash`、`powershell`、`json`、`yaml`、`text` 五种语言与一个深色主题（代码块底为 `--code-bg`）；输出带 `style` 属性的 HTML，运行时零 JS |
| 行内徽标与按键 | 自写 markdown-it 规则（约 40 行） | 行内代码内容为 `status:<值>` 或 `level:<值>`（值见 §5）时输出 `<ZtStatus>`，值不在 §5 列表内时构建失败；以 `kbd:` 开头时输出 `<Kbd>` |
| frontmatter | `unplugin-vue-markdown` 自带 | `frontmatter: true`、`exposeFrontmatter: true`、`headEnabled: false` |

所有包锁定精确版本（与 00 章 §5.1 一致）。`markdown-it` 设 `html: false`、`linkify: false`、`typographer: false`。

**理由**：

1. 容器要渲染成可交互的 Vue 组件（复制按钮、可复制的说法、发布卡片）。编译成 SFC 后，容器直接输出 `<Callout type="confirm">`、`<ExampleUtterances>` 等组件标签，与站内其它组件共用一套设计变量、预渲染与水合，不需要在 `v-html` 里做事件委托。
2. 每页编译为独立组件，路由按页懒加载（`() => import('../docs/install.md')`），首页不为文档付出任何体积。
3. 高亮、锚点、FileTree 解析都在构建期完成，访客浏览器不下载 Markdown 解析器与高亮器。shiki 输出的内联 `style` 符合现有 CSP（`style-src 'self' 'unsafe-inline'`，`script-src 'self'`）。
4. 与现有 Vite 7 + Vue 3.5 + SSR 预渲染链路直接衔接，不引入第二套构建。

**不选**：

| 方案 | 不选的原因 |
|---|---|
| VitePress | 自带一套应用、路由与主题；要与门户首页共用顶栏、设计变量与预渲染，就得维护两套构建与两份样式 |
| 运行时解析 Markdown（`marked` 等在浏览器跑） | 每页多下载解析器与高亮器；首屏要等脚本执行才有正文，违背 00 章 §5.5「内容先可见」 |
| 构建期转 HTML 字符串 + `v-html` | 交互组件只能靠事件委托补，复制按钮与发布卡片的状态管理分散；无法复用 `ZtStatus` 等组件 |
| highlight.js / Prism 运行时高亮 | 运行时体积；与构建期方案相比没有收益 |

**插值转义**：SFC 模板会把 `{{ }}` 当作 Vue 插值。markdown-it 渲染器把正文与行内代码中的 `{` `}` 输出为 `&#123;` `&#125;`，代码块组件加 `v-pre`。构建期检查生成的模板里没有未转义的 `{{`，正文里出现的 `{{字段}}`（如项目说明模板占位符）原样显示。

### 3.4 清单虚拟模块与目录

`build/docs-plugin.ts` 在构建开始时读取全部 `src/docs/*.md`，解析 frontmatter 与 H2/H3 标题，生成虚拟模块 `virtual:docs-manifest`：

```ts
export interface DocHeading { level: 2 | 3; text: string; id: string }
export interface DocEntry {
  slug: string;          // 'install'、'features/check'；首页 'index'
  path: string;          // '/docs/install/'；首页 '/docs/'
  title: string;
  group: string;
  order: number;
  summary: string;
  updated: string;       // 'YYYY-MM-DD'
  headings: DocHeading[]; // 本页目录用；id 由 docs-slug.ts 生成
}
export const docs: DocEntry[];        // 按组顺序、组内 order 排好
export const groups: { name: string; description: string; items: DocEntry[] }[];
```

`router.ts` 用 `docs` 生成文档路由，每页组件 `() => import(`../docs/${file}.md`)`。清单只含标题与摘要，23 页约 10 KB（gzip 前），随文档布局块加载。

### 3.5 预渲染

现 `scripts/prerender.mjs` 只渲染首页。改为：

1. `entry-server.ts` 导出 `render(url: string): Promise<{ html: string; head: string; status: 200 | 404 }>`：新建 `createSSRApp` 与内存历史的 router，`router.push(url)`，`await router.isReady()`，`renderToString`；`head` 由路由元信息生成（下表）。同时导出 `routes: string[]`（`/`、`/docs/`、每个文档页）。
2. `index.html` 的 `<head>` 内加 `<!--app-head-->` 占位，`<title>` 与 description 从模板中移出，改由 `head` 填入。
3. `prerender.mjs` 遍历 `routes`，把结果写到 `dist/<路径>/index.html`（`/` → `dist/index.html`，`/docs/install/` → `dist/docs/install/index.html`）；再渲染一个不存在的路径（`/__not_found__/`）写到 `dist/404.html`。
4. 每个文档页输出后校验：HTML 里有该页 `title` 作为 H1、清单里该页每个标题 id 都出现在 HTML 中；任何一项不满足则构建失败。
5. 生成 `dist/sitemap.xml`（全部 `routes`，文档页 `lastmod` 取 `updated`，首页取构建日期，`loc` 用 `https://ztsgai.com` + 路径）与 `dist/robots.txt`（`User-agent: *`、`Allow: /`、`Sitemap: https://ztsgai.com/sitemap.xml`）。

| 页面 | `<title>` | `<meta name="description">` | `<link rel="canonical">` |
|---|---|---|---|
| 文档首页 | `文档 · 智通数工AI` | index.md 的 `summary` | `https://ztsgai.com/docs/` |
| 文档页 | `<title> · 文档 · 智通数工AI` | 该页 `summary` | `https://ztsgai.com/docs/<slug>/` |
| 404 | `页面不存在 · 智通数工AI` | 不输出 | 不输出；另加 `<meta name="robots" content="noindex">` |

前端路由切换后由 `router.afterEach` 更新 `document.title` 与 description，不引入 head 管理库。

`main.ts` 改为：先 `await router.isReady()` 再 `app.mount('#app')`，预渲染页面走 `createSSRApp` 水合。

### 3.6 `base` 改动

`vite.config.ts` 现为 `base: './'`（相对路径，便于目录部署）。文档页位于 `/docs/install/` 这类二级目录，相对路径会把 `assets/` 解析到 `/docs/install/assets/`。改为 `base: '/'`，站点只部署在域名根（`/opt/ztsgai/site` → `https://ztsgai.com/`）。`site/README.md` 中「资源使用相对路径，支持目录部署」一句随之删除。

### 3.7 部署件改动

`zhitong/portal/deploy/nginx/ztsgai.conf` 的 443 主站 `server` 块，在 `location /` 之前加：

```nginx
    # 不存在的路径返回 404 状态与门户的 404 页（error_page 在各 location 继承）。
    error_page 404 /404.html;
```

不需要其它改动：`location /` 的 `try_files $uri $uri/ =404` 已能按目录取 `docs/<slug>/index.html`，也会把无尾斜杠的目录地址 301 到带斜杠地址；`sitemap.xml`、`robots.txt` 是普通静态文件，按默认 `Cache-Control: no-cache` 返回。

`deploy.sh` 的发布后 curl 校验增加三项：`/docs/` 返回 200；`/docs/install/` 返回 200 且正文含「安装」；`/docs/__missing__/` 返回 404 且正文含「页面不存在」。`runbook.md` 第 3.4 节同步写明这三项。

### 3.8 构建期检查

`docs-plugin.ts` 在 `buildStart` 执行下列检查，任一失败即中止构建并打印「文件:行号 原因」：

1. §1.1 每行都有文件，`src/docs/` 下每个 `.md` 都在 §1.1 中。
2. frontmatter 字段齐全、无多余字段、`title`/`slug`/`group`/`order` 与 §1.1 一致、`summary` ≤ 60 字、`updated` 格式正确。
3. `sources` 每条路径在仓库中存在。
4. 站内链接与锚点都能解析（§2.5）。
5. 能力页（`features-*.md`）的 H2 恰为 §6.2 的 11 个标题且顺序一致；没有 H4 及更深标题；H1 不出现在正文（H1 由布局用 `title` 渲染）。
6. 容器名只用 §5 列出的；容器不嵌套；`::: doc-cards` 只出现在 `index.md`。
7. 正文不含原始 HTML 标签（`html: false` 会把它当文本显示，检查是为了尽早发现写错）。
8. 搜索索引不超过 §8.6 预算。

## 4. 页面布局

### 4.1 断点

文档沿用 00 章 §4.4 的断点，另加一个文档专用断点 1200px（三栏的最小宽度）。

| 宽度 | 布局 | 左右边距 |
|---|---|---|
| ≥ 1200px | 三栏：侧栏 240px · 正文 ≤ 760px · 本页目录 200px，栏间距 24px；整体最大宽 1248px 居中 | `max((视口 − 1248) / 2, 32px)` |
| 1024–1199px | 两栏：侧栏 240px · 正文 ≤ 760px，栏间距 24px；本页目录改为正文顶部的折叠块 | 32px |
| 768–1023px | 单栏：正文 ≤ 760px 居中；侧栏改为抽屉；本页目录为正文顶部折叠块 | 48px |
| ≤ 767px | 单栏；侧栏为抽屉；本页目录为折叠块 | 20px |

## 5. Markdown 扩展语法

正文是标准 Markdown（CommonMark + GFM 表格），另加以下扩展。不允许在正文里写原始 HTML。

| 写法 | 渲染为 | 用途 |
|---|---|---|
| `::: note 标题`…`:::` | Callout「注意」 | 不照做会出错、丢数据或得到错误结论 |
| `::: tip 标题`…`:::` | Callout「提示」 | 更省事的做法、可选的做法 |
| `::: confirm 标题`…`:::` | Callout「需人工确认」 | 结果中必须由人复核或签字的内容 |
| `::: steps`…`:::`，内含有序列表 | Steps | 操作步骤；每个列表项是一步，项内可有段落、图片、代码块 |
| `::: filetree 标题`…`:::`，内含 ```` ```text ```` 代码块 | FileTree | 目录与文件位置；标题可省略；两个空格一级缩进，目录名以 `/` 结尾，`#` 后为行注释 |
| `::: utterances`…`:::`，内含无序列表 | ExampleUtterance 一组 | "您可以这样说"；每个列表项一条，可复制 |
| `` `status:ok` `` `` `status:partial` `` `` `status:empty` `` `` `status:insufficient` `` | 结果状态徽标：完成 / 部分完成 / 无结果 / 资料不足 | 行内 |
| `` `level:error` `` `` `level:warn` `` `` `level:info` `` | 告警级别徽标：错误 / 警告 / 提示 | 行内 |
| `` `status:manual` `` | 徽标"需人工确认" | 行内 |
| `` `kbd:Ctrl+K` `` | Kbd 按键组 | 行内；`+` 分隔多个键 |
| ```` ```bash ```` / ```` ```powershell ```` / ```` ```text ```` 等 | 代码块（带复制按钮） | 命令、文件内容 |
| `[文字](/docs/install/)` | 站内链接 | 一律以 `/docs/` 开头、以 `/` 结尾；页内锚点写 `/docs/install/#校验安装包` |
| `::: doc-cards`（空容器） | DocCards | 只用于 `index.md`：按 §1.2 渲染 6 张组卡片 |
| `::: release-current`（空容器） | ReleaseCurrent | 当前发布的版本、日期、各平台文件、大小、SHA256 与下载按钮，数据来自 `public/downloads/releases.json`（§7.13） |

Callout 标题可省略，省略时显示类型名。容器不嵌套容器（`steps` 内可以有代码块，不能再有 `:::`）。

写作约定（所有正文）：

- 命令代码块里不写提示符（`$`、`PS>`），复制即可运行；需要用户替换的部分写成中文尖括号占位，如 `<安装包文件名>`。
- 金额、面积一律与 00 章 §8 的示例数字一致，并在出现处写「示例」。
- 不出现 API Key、AK/SK、真实桶名、真实客户名；示例桶名写 `zt-company`，示例公司写「某某工程造价咨询有限公司」（与 `CONFIG-PACKAGE.md` 一致）。

## 6. 能力页模板

`文档内容/features-*.md` 共 12 页，全部使用同一套 frontmatter 与同一组 H2 标题，顺序固定，不增不减。某节确实无内容时保留标题，正文写"无。"并用一句话说明原因。

### 6.1 frontmatter

```yaml
---
title: 送审审定核对          # 与路由表"标题"一致
slug: features/check         # 与路由表 slug 一致，不带前后斜杠
group: 核对与测算             # 开始使用 / 项目与资料 / 核对与测算 / 成果与归档 / 知识与协作 / 参考
order: 1                     # 组内序，从 1 起，取 §1.1「组内序」列（项目与资料组的 1 是 projects.md）
summary: 一句话说明，≤ 60 字   # 用于文档首页卡片、搜索结果摘要、<meta name="description">
updated: 2026-10-20
sources:                     # 本页依据的仓库路径，至少一条
  - zhitong/skills/zt-reconcile/SKILL.md
---
```

### 6.2 H2 标题（按此顺序）

| # | H2 | 写什么 |
|---|---|---|
| 1 | 一句话 | 一段，≤ 60 字，说清"根据什么资料、产出什么、需要谁确认" |
| 2 | 适用场景 | 3–5 条列表，每条以岗位或工作节点开头 |
| 3 | 您可以这样说 | 一个 `::: utterances` 块（§5），3–6 条；用户原话，口语，带项目编号 2026-007 |
| 4 | 需要准备的资料 | 表格：资料 / 放在哪里（桶内路径）/ 格式要求 / 必需或可选 |
| 5 | 它会怎么做 | 步骤：`::: steps` 编号步骤；每步写用户能看到的现象（工具调用条、确认提问），工具名用 `` `等宽原名` `` 跟在中文后 |
| 6 | 得到什么 | 文件与位置：`::: filetree` 显示落盘位置，再用表格解释每个文件 |
| 7 | 结果怎么读 | 结果状态与告警的含义（链接 [结果状态与告警](/docs/results/)）；示例数字取自 00 章 §8 |
| 8 | 需要您确认的事项 | 一个 `::: confirm` 块，内为列表，逐项写需人工确认的内容 |
| 9 | 限制与注意 | 列表；未签核数据、格式限制、估算值等限定照搬来源 |
| 10 | 常见问题 | H3 为问题，正文为答案；3–6 问 |
| 11 | 相关能力 | 2–4 条站内链接，每条后跟一句为什么相关 |

H2 文字逐字照上表第二列（不带括号说明）。H3 只在"常见问题"和"它会怎么做"（需要分阶段时）中使用。不写 H4。

非能力页（开始使用、项目与存储桶目录、参考组）不受 §6.2 约束，但同样不写 H4，H2 数量不少于 3（本页目录才有意义）。

## 8. 站内搜索

### 8.1 入口

- 侧栏顶部按钮：外观像输入框，左放大镜图标，文字「搜索文档」，右侧按键提示（Apple 设备显示 `⌘ K`，其它显示 `Ctrl K`；按键提示在水合后才渲染，预渲染 HTML 中没有，避免平台判断不一致）。
- 文档首页深色区里的大号触发器（§4.4），占位文字「搜索安装、配置包、核对、需人工确认…」。
- 平板与手机：文档子栏右侧图标按钮。
- 快捷键：在 `/docs/` 下任一页面，`⌘K`（macOS）/ `Ctrl+K`（其它）打开；焦点不在输入框、文本域、可编辑元素中时，按 `/` 也打开。首页（`/`）不绑定这些快捷键。

### 8.2 对话框

- `BaseDialog`（原生模态 `<dialog>`），桌面宽 640px、距顶 12vh、最大高 70vh；手机全屏。打开时焦点在输入框；关闭后焦点回到触发它的元素。
- 结构：输入框（`role="combobox"`、`aria-expanded`、`aria-controls="docs-search-results"`、`aria-autocomplete="list"`、`aria-activedescendant`）+ 结果列表（`role="listbox"`，每项 `role="option"`）+ 底部操作提示（`↑↓ 选择 · Enter 打开 · Esc 关闭`，手机不显示）。
- 输入防抖 80ms；每次结果更新后，隐藏的 `aria-live="polite"` 区朗读「找到 {n} 条结果」或「没有结果」。
- 键盘：`↑`/`↓` 在结果间移动（循环），`Enter` 打开当前项并关闭对话框，`Esc` 关闭；鼠标悬停也会改变当前项。
- 结果项：第一行页标题（14px / 600）+ ` › ` + 小节标题；第二行摘录（14px，`--text-muted`，最多两行）；命中文字用 `<mark>`（底 `--warning-bg`，字色不变）。结果按页分组，每页最多 3 个小节，总数最多 20 条。
- 文案：
  - 输入框占位「搜索文档」，`aria-label="搜索文档"`
  - 索引加载中「正在载入索引…」
  - 空输入时显示「常用：」+ 四个快捷词按钮：`安装`、`配置包`、`需人工确认`、`报错`
  - 无结果「没有找到与“{q}”相关的内容。可以换个说法，或查看」+ 链接「常见问题与排错」（`/docs/troubleshooting/`）
  - 索引加载失败「搜索索引载入失败，请刷新页面后重试。」

### 8.3 索引生成（构建期）

`docs-plugin.ts` 在 `generateBundle` 阶段为每页按 H2/H3 切分小节（H2 之前的导语归入「概述」），去掉 Markdown 标记后得到纯文本（表格按行拼接，`::: utterances` 的说法、代码块内容都保留，以便能搜到 `shasum`、`zt_not_importable` 这类词）。输出一个带内容哈希的静态资源 `assets/search-index-<hash>.json`（由 nginx 的 `/assets/` 规则按一年不可变缓存），文件 URL 注入搜索模块：

```json
{
  "v": 1,
  "pages": [{ "p": "/docs/install/", "t": "安装", "g": "开始使用" }],
  "sections": [{ "d": 0, "h": "校验安装包", "a": "校验安装包", "x": "下载完成后，先核对文件的 SHA256…" }]
}
```

`d` 是 `pages` 下标，`a` 是锚点 id，`x` 是纯文本。倒排索引不预先生成（二字切分会让文件膨胀数倍），由浏览器在首次打开对话框时建立。

### 8.4 分词与检索（浏览器）

1. 规范化：`NFKC`（全角转半角）、英文小写、去掉空白与标点。
2. 切分：连续汉字切成重叠二字组（「校验安装包」→ 校验、验安、安装、装包）；查询只有一个汉字时用单字；连续字母数字（含 `_`）为一个词，查询词长度 ≥ 2 时按前缀匹配（`zt_not` 命中 `zt_not_importable`）。
3. 首次打开时为全部小节建立 `Map<词, Set<小节下标>>`，分别为标题、小节标题、正文建三张表；建立耗时预算 ≤ 30ms（中端笔记本）。
4. 同义词扩展：查询词命中 `search-synonyms.json` 时，同组词按「或」参与匹配。初始表：`核减`↔`审减`；`核增`↔`审增`；`密钥`↔`AK`↔`SK`↔`访问密钥`；`桶`↔`存储桶`↔`TOS`；`报错`↔`错误`↔`失败`；`配置包`↔`zhitong.config.json`；`装不上`↔`安装`。
5. 评分：小节至少命中查询词组的 70% 才入选；每个命中词：页标题 +8、小节标题 +4、正文 +1（同一词在正文最多计 3 次）；规范化后的整句查询在小节标题或正文中原样出现再 +10。同分时按清单顺序。
6. 摘录：以第一个整句命中处（没有则第一个词命中处）为中心取前后各 40 字，首尾加「…」；把所有命中词的区间合并后包 `<mark>`。用文本节点拼装，不用 `innerHTML`。

### 8.5 加载时机

搜索逻辑是独立的懒加载块：指针移到或聚焦任一搜索触发器时预取（`import()` + `fetch` 索引），首次打开对话框时若未就绪显示「正在载入索引…」。索引只取一次，之后在内存中复用。`fetch` 走同源，符合 CSP `connect-src 'self'`。

### 8.6 体积预算

| 项 | 预算（gzip） | 超出时 |
|---|---|---|
| 搜索逻辑块 | ≤ 6 KB | 构建失败 |
| 索引 JSON | ≤ 120 KB（未压缩 ≤ 480 KB） | 构建失败；先删减索引中的代码块内容，再考虑分组拆分 |

按当前 23 页估算，纯文本约 13–15 万字，UTF-8 约 420 KB，gzip 后约 100 KB。

## 9. 动效

文档是查阅型页面，动效只用于表达位置变化，不做入场动画。

### 9.1 不使用的

- **不启用 Lenis**：长文阅读需要浏览器原生的滚动、页内查找（⌘F 后的跳转）、锚点定位与辅助技术的滚动行为；阻尼滚动会让这些跳转和本页目录的定位变慢、变不准。Lenis 实例只由 `HomePage` 创建，离开首页时销毁（00 章 §5.3 的 `smooth-scroll.ts` 提供 `destroy()`）。
- 文档路由不加载 GSAP 与 ScrollTrigger（文档自身的动效全部是 CSS 过渡）；顶栏若按 01 章懒加载 GSAP，由顶栏自行负责。
- 正文、Callout、Steps、表格没有入场动画，没有 `data-reveal`：预渲染即终态，打印与截图完整（00 章 §5.5）。

### 9.2 使用的

| 动效 | 目标 | 属性与数值 | 时长与缓动 |
|---|---|---|---|
| 页面切换 | 正文列 `.docs-main` | `opacity 0 → 1`（只淡入，不位移；侧栏与本页目录不动） | `--dur-micro`（160ms），`--ease-out`；Vue `<Transition mode="out-in">`，离开 0ms |
| 本页目录指示条 | 2px 竖条 | `transform: translateY(当前项 top)` 与 `scaleY(当前项高 / 基准高)` | `--dur-short`（280ms），`--ease-out` |
| 侧栏悬停 | 条目底色 | `background-color` | `--dur-micro` |
| 抽屉 | 抽屉面板 / 遮罩 | `translateX(-100% → 0)` / `opacity 0 → 0.4` | `--dur-short`，`--ease-out`；关闭 `--dur-micro` |
| 搜索对话框 | 对话框 | `opacity 0 → 1`、`scale(0.98 → 1)` | `--dur-micro`，`--ease-out` |
| 复制反馈 | 图标 | 复制图标与对勾交叉淡入 | `--dur-micro` |

本页目录指示条用 `useHoverIndicator`（00 章 §6.2）的 `driver: 'css'` 方式（01 章 §14.4，文档页不加载 GSAP）与「跟随选中项」能力，选中项为滚动定位的当前项；目录里不启用悬停预览（指针在目录上移动时指示条不跟随指针，避免与阅读位置混淆）。

### 9.3 锚点与滚动

- 点击本页目录条目、`HeadingAnchor`：`element.scrollIntoView({ behavior: 减少动效 ? 'instant' : 'smooth', block: 'start' })`（依赖 `scroll-margin-top`），随后 `history.replaceState` 写入 `#id`，并把焦点移到该标题（`tabindex="-1"`，`preventScroll: true`）。
- 跨页链接带锚点（`/docs/install/#校验安装包`）：路由 `scrollBehavior` 在新页渲染后定位到该标题，`behavior: 'instant'`。
- 浏览器前进/后退：恢复 `savedPosition`。其余跳转：回到页顶。

### 9.4 减少动效

`prefers-reduced-motion: reduce` 时：页面切换无淡入；指示条与抽屉直接到位（过渡时长 0）；锚点跳转为 `instant`；搜索对话框直接出现。

## 11. 无障碍

- 地标：`header`、`nav[aria-label="文档"]`（侧栏）、`main`、`nav[aria-label="本页目录"]`、`nav[aria-label="面包屑"]`、`footer`。

- 颜色不是唯一信息：Callout、状态徽标都有文字；表格中的核增核减同时写「核增 / 核减」。
- 触控目标 ≥ 44×44px（侧栏条目、上一页/下一页、复制按钮、子栏按钮）。
- 页面缩放到 200% 时无横向滚动、无内容遮挡（表格除外，表格在自身容器内滚动）。
