# 07 装饰动效

本章规定门户上代码绘制的装饰：首屏背景、安装区面板、页脚、章节接缝、404 页、深色区底纹。装饰不传达信息，去掉后页面内容与功能完全不变。设计概念、颜色、动效变量、`useInView`、减少动效与性能预算沿用 [00 章](00-总览与设计系统.md) §4.1、§4.2、§5、§6.8、§9。每一项都有可直接打开的参考实现，放在 [动效参考/](动效参考/index.html)：零依赖、零外部请求，带“重播 / 静态终帧”开关与每帧耗时显示。实测数据见 §11。

## 1. 原则

1. **只用底稿词汇**：网格、轴线与轴号（GB/T 50001，轴号不用 I、O、Z）、尺寸线与 45° 起止符、标高符号、图框与标题栏、修订云线、索引符号、审核章、12 位清单编码。不用 00 §4.1 排除的渐变球、星空、霓虹、3D 人物。
2. **不传达信息**：装饰根元素 `aria-hidden="true"`，不含可聚焦元素，`pointer-events: none`。需要指针时监听父元素（被动监听）。装饰里出现的文字（轴号、编码、标高、“缺页”）在页面其它地方都有正式表达，或者本身没有含义。
3. **不抢焦点**：只放在背景与空白处，不进入工作示例窗口、12 项能力小动画、数据流图、说明卡、弹层。同屏最多一个装饰处于运行态（§3.3 调度器）。装饰的入场排在首屏可交互之后（00 §5.4.6）。
4. **内容先可见**：预渲染 HTML 只含装饰的静态底（CSS 网格或静态 SVG）。JS 未加载、加载失败、减少动效时，内容完整；装饰显示静态底或静态终帧。
5. **只在需要时绘制**：所有循环挂在 `useInView`（00 §6.8）与 `visibilitychange` 上；画面静止后循环休眠，直到下一次输入或滚动唤醒；Canvas 设备像素比上限 2；每帧组件脚本 ≤ 3 ms（00 §9），超出时自动降级（§3.2）。
6. **不改光标**：系统光标始终可见。D1 的“十字光标”是画在背景里的图形，不替换光标。

### 3.1 接口

```ts
export type DecoMode = 'live' | 'once' | 'still';
export interface DecoLoopOptions {
  /** 可见比例阈值，默认 0.25；挂 00 §6.8 的 useInView */
  threshold?: number;
  /** 一帧。t 为组件内部时钟（只在运行时前进，暂停后从原处继续），dt 截到 ≤ 0.05 s。
   *  返回 false 表示画面已静止：循环休眠，直到 wake()。 */
  tick(t: number, dt: number): boolean;
  /** 尺寸或 DPR 变化后重建（cssW、cssH 为 CSS 像素，dpr 已封顶） */
  resize(cssW: number, cssH: number, dpr: number): void;
  /** 绘制静态终帧：减少动效、'once' 播放结束、调度器挂起时调用 */
  still(): void;
  dprCap?: number;    // 默认 2
  budgetMs?: number;  // 默认 3
}
export interface DecoLoop {
  readonly mode: DecoMode;
  readonly running: boolean;
  wake(): void;       // 指针、滚动等输入后调用
  replay(): void;     // 时钟归零重新入场
  destroy(): void;    // 组件卸载时：取消 rAF，断开所有 Observer 与监听
}
export function createDecoLoop(host: HTMLElement, canvas: HTMLCanvasElement | null, opts: DecoLoopOptions): DecoLoop;
```

### 3.2 行为

1. **启动**：组件 `onMounted` 后等 `requestIdleCallback(…, { timeout: 1500 })`（不支持时 `setTimeout` 1500 ms），再等 `document.fonts.ready`（画布文字用自托管 IBM Plex Mono）。启动前组件只渲染静态底。
2. **模式**：减少动效 → `still`；`(hover: hover) and (pointer: fine)` 且视口 ≥ 768px → `live`；否则 `once`，只播放入场，结束后停在终帧并不再请求帧。`prefers-reduced-motion` 变化时整体重建。
3. **可见性**：可见比例 < `threshold` 或 `document.hidden` 时取消 rAF，内部时钟停止，恢复后从原处继续，不重播。
4. **尺寸**：`ResizeObserver` 观察宿主；`dpr = min(devicePixelRatio, dprCap)`；画布 `width = round(cssW × dpr)`，`setTransform(dpr, 0, 0, dpr, 0, 0)`；1px 线画在 `round(v) + 0.5`。
5. **预算守卫**：每帧计时 `tick`。连续 90 帧超过 `budgetMs` 时，`dprCap` 降为 1 并重建一次。D2 另有绘制预算（§6.3 第 8 步）。开发构建用 `performance.measure('deco:<编号>')` 记录每帧耗时，供 §11 的测试读取。
6. **卸载**：`HomePage` 离开时（01 §13）调用 `destroy()`。组件不在 `window` 上留下任何监听。
7. **加载**：五个组件都用 `defineAsyncComponent` 懒加载，各成一块，只在客户端挂载；SSR 只输出静态底。D5 例外：它的 SVG 在 SSR 时生成并进入 `404.html`。

### 3.3 同屏调度 `decoScheduler.ts`

处于 `live` 的装饰向调度器登记可见比例。同一时刻只有可见比例最大的那一个运行待机动画（D2 的闪烁与扫光、D3 的缓摆），其余调用 `still()` 并休眠，可见比例变化时重新分配。入场动画不受调度限制，但每个装饰只有一次入场。D1 的指针响应、D4 的滚动标注属于对用户输入的响应，不参与调度。

## 5. D1 首屏底稿网格 `DecoHeroGrid`

**概念**：首屏是一张刚铺开的底稿。轴网从原点画出，轴号落位；精确指针下，背景里有一个 CAD 十字光标吸附到网格交点，读出以毫米计的坐标；压到主轴线时，对应轴号点亮。

### 5.1 位置与尺寸

| 宽度 | 范围 | 层级 | 模式 |
|---|---|---|---|
| ≥ 1280 | `section.hero` 全宽 × 全高，`position: absolute; inset: 0` | `z-index: 0`；内容层 `z-index: 1`；示例窗口不透明，自然遮住装饰 | `live` |
| 1024–1279 | 同上（文案与示例上下堆叠） | 同上 | `live` |
| 768–1023 | 同上 | 同上 | 精确指针 `live`，否则 `once` |
| ≤ 767 | 同上 | 同上 | 只画一次静态帧，不画左侧轴号，不注册指针监听，释放动态层画布（宽高置 0） |

轴 1 与内容容器左缘重合，第一条水平主线 `originTop` 取 `section.hero` 的上内边距（02 §1.3：≥ 1440 为 56px），文案因此落在格线上。顶部轴号行圆心 `y = 20`；左侧轴号列圆心 `x = 容器左缘 − 48`，左边距不足 `48 + 10 + 6` px 时不画左侧轴号。

### 5.2 技术

- CSS：`.bp-paper` 用两层 `linear-gradient` 画 24px 细网格（`rgba(220,232,244,.72)`，即 `--grid-line` 72%），`background-position` 对齐 `(x0 mod 24, originTop mod 24)`，`mask-image: linear-gradient(to bottom, #000 62%, transparent)`。这一层在预渲染 HTML 里就有，不依赖 JS。
- 静态层 canvas（与 `.bp-paper` 同一遮罩）：主线 `#d3e0ef` 与轴号（白底、`#bfd0e6` 边、`#7189a8` 10px 等宽字）。入场后冻结，不再重绘。也可以换成内联 SVG，行为等价，还省一张画布。
- 动态层 canvas（不加遮罩）：透镜、十字、读数、轴号高亮、落点标记。

### 5.3 算法

1. **布局**：竖主线 `x = x0 + k·120`（`k ≥ 0`，`x ≤ W − 16`），编号 1、2、3…；横主线 `y = originTop + j·120`（`y ≤ H − bottomClear`），最低一条为 A，向上依次 B、C…（跳过 I、O、Z）。原点为 1/A。
2. **入场**：第 i 条线延迟 `i × 0.045 s`，长度 = `expo.out(进度)`，从轴号一端画向远端，时长 0.9 s；轴号以 `back.out` 从 0 放大到 1。总时长约 `0.9 + 0.045 × max(竖线数, 横线数)` ≈ 1.4 s。入场进行到 55% 时十字出现在 1/F（左上主交点），以 ω = 6 rad/s 滑到原点 1/A，读数“X 0  Y 0”，两个轴号点亮。
3. **吸附**：`pointermove`（被动，只认 `mouse`/`pen`）→ 目标 = 最近的 24px 交点。十字位置用临界阻尼弹簧的解析解逼近目标，任意 dt 都稳定：`e = x − 目标; k = (v + ωe)·dt; x = 目标 + (e + k)·e^(−ω·dt); v = (v − ωk)·e^(−ω·dt)`，跟随时 ω = 28。
4. **落点标记**：目标换到新交点时，旧交点留一个 9px 的“+”（accent），α = 0.5 × (1 − 年龄/0.9 s)²，最多 14 个。同时选框做一次脉冲：半边长 `4.5 + 3·p`，`p` 从 1 按 `e^(−12t)` 衰减。
5. **透镜**：以指针为圆心、半径 168px，用径向渐变（中心 `rgba(6,102,245,.3)` → 透明）重描半径内的细格线。圆心按速率 30 的指数逼近指针，强度在进入与离开时按速率 6 渐变。
6. **十字与读数**：横、竖各一条 1px 线，线性渐变两端透明、中心 α 0.5，半长分别为宽的 0.42、高的 0.62。选框 9px，白底、1.25px accent 边。读数 = (目标 − 原点) / 24 × 300 mm，格式 `X 4500  Y 2100`，10.5px 等宽，白底、1px `#dce8f4` 边，放在选框右上 (14, −30)；若与 `[data-deco-avoid]` 的矩形或右缘相交，翻到左侧。
7. **轴号高亮**：目标恰好落在主线上时，这条轴线全长以 accent α 0.35 再描一遍，轴号填 accent、字变白；高亮量按速率 14 渐变。
8. **离开**：指针离开 `section.hero` 或进入 `[data-deco-avoid]` 时，目标回到原点（ω = 6），十字 α 降到 0.6。
9. **休眠**：弹簧残差 < 0.05px 且速度 < 0.5px/s，透镜、高亮、透明度都已收敛，且没有落点标记时，`tick` 返回 false，循环休眠到下一次 `pointermove`。实测指针停下 0.85 s 后进入休眠。

### 5.5 性能、降级、无障碍

- 入场约 85 帧，之后只在指针移动时运行。实测指针连续移动时 0.19–0.23 ms/帧，峰值通常 ≤ 1.0 ms；含入场的峰值 1.1 ms（DPR 2）。首帧前在 `init` 里预先设置画布字体（`measureText`），避免第一帧付字体解析的开销（未预热时第一帧 4 ms）。
- 显存：1440×800、DPR 2 时每张画布约 18 MB。手机只保留静态层。
- 减少动效：静态终帧（主线、轴号、十字停在 1/A、读数“X 0  Y 0”），不响应指针。
- 无 JS 或组件加载失败：只有 CSS 细网格。
- 打印：两张画布 `display: none`，细网格保留。
- `aria-hidden="true"`；不改变 `cursor`；不拦截点击。

## 6. D2 清单编码字符场 `DecoInstallField`

**概念**：交付的是一份“盖了章”的配置。安装面板的底纹由 12 位清单编码组成（取 00 §8.2 各章的 GB 50854 编码，如 `010502001001` 矩形柱、`010902001001` 屋面卷材防水、`011701001001` 综合脚手架）。面板进入视口时，编码从乱码中由内向外逐格落定，汇成品牌图形：渐变方块、白色十字、四段绿短划。图形从面板右下角出血，像证书的防伪底纹，在内容下方自动压暗。

### 6.1 位置与尺寸（05 §3.3 插槽）

- `<DecoInstallField>` 是 `.install-panel` 的第一个子元素，`position: absolute; inset: 0; z-index: 0; pointer-events: none; aria-hidden="true"`。画布只覆盖“字符场区域”（品牌图形 ± 光晕，与面板求交），不铺满整块面板。
- 图形边长 S 与中心：

| 面板宽 | S | 中心 | 格距（`round(S/54)`，6–14px） |
|---|---|---|---|
| ≥ 900（桌面两栏，约 1248×760） | `min(0.82·H, 0.5·W)` ≈ 623 | `(W − 0.22S, H − 0.26S)` | 12px，格高 19，字 16px，约 1,730 格 |
| < 900（平板、手机单栏） | `0.92·W` | `(W − 0.2S, H − 0.3S)` | 手机 7px，格高 11 |

### 6.2 品牌图形的来源

`brandMark.ts` 以 `import raw from '../../../assets/brand-mark.svg?raw'` 读取品牌 SVG，用 `DOMParser` 解析出 `viewBox`、`rect`（宽高、`rx`）、`linearGradient`（`x1..y2` 与 stops）、`g` 的 `rotate(θ cx cy)`，以及每条 `path` 的 `d`、`stroke`、`stroke-width`、`stroke-linecap`。白色描边归“白”类，其它描边归“强调”类。品牌图形换稿时，字符场随之改变，无需改代码（品牌 README：唯一来源是 `brand-mark.svg`）。绘制只用 `Path2D` 与 `roundRect`，不用 `<img>` 加载 SVG，画布不会被污染，`getImageData` 在各浏览器都可用。

### 6.3 算法

1. **采样**：在区域大小的离屏画布上按 SVG 几何绘制：方块填 `#f00`，白描边 `#0f0`，强调描边 `#00f`，后画的覆盖先画的。`getImageData` 一次，对每格平均 `(R·A, G·A, B·A)`：G > 0.3 → 白类；B > 0.3 → 强调类；R+G+B > 0.12 → 主体；否则为场。主体的色阶 = 格中心在方块局部坐标里对渐变轴的投影，量化为 12 级。
2. **字符流**：第 r 行从编码表第 `7r` 项开始，按“编码 + 空格”拼接，行首错开 `(5r) mod 13` 格。空格在图形内显示为“·”，在图形外留空。
3. **透明度**：白类、强调类 = `min(1, 覆盖率/0.55)`，粗体；主体 = `0.92 × 覆盖率^0.7`，并在格底加一块 α 为 0.12 的同色方块，白类、强调类的方块 α 为 0.3，使轮廓成形；场 = `U(0.07, 0.2) × (1 − smoothstep(0, 1, sdf / 0.2S))`，sdf 为格中心到圆角方块的有符号距离，场沿图形轮廓向外淡出。
4. **内容压暗（对比度保障）**：取面板内容层中 `h2, h3, p, li, dt, dd, a, button, [data-deco-safe]` 及平台卡的盒子，各外扩 8px；落在其中的格子 α 封顶：场 0.08、主体 0.22、白 0.18、强调 0.2，叠加高光 ≤ 0.05。依据：白 α 0.18 合成在 `#082457` 上后亮度 L ≈ 0.071；05 的次要文字（76% 白）L ≈ 0.58，对比 (0.58+0.05)/(0.071+0.05) = 5.2 ≥ 4.5，纯白字为 8.7。进入视口 1.2 s 后（入场位移已结束），在 idle 回调里重测一次，只重画标志变化的格子。
5. **入场**：`lockAt = 0.45 + (图形内 ? 0.95·s : 0.52 + 0.8·d) + 0.25·rand`，s 为到图形中心的距离 / 0.72S，d 为场的归一化距离。锁定前每格以约 15 Hz 显示随机数字（场色、α 0.1–0.22）。锁定瞬间叠白：`(1 − Δt/0.55)² ×（图形内 0.9，场 0.45）`。约 2.0 s 全部锁定，叠白在其后 0.55 s 内褪尽。
6. **待机**（仅 `live`，受 §3.3 调度）：每秒约 1.2% 的格子重新乱码 0.25–0.6 s；每 8 s 一道 45° 扫光，1.6 s 扫过，带宽 0.12，峰值叠白 0.42；精确指针 40px 内的非内容格子“解码”0.3–0.55 s 后复原。
7. **绘制**：字形图集按 DPR 预渲染。行为 12 级渐变（常规体）、白（粗）、强调（粗）、场色、白常规、白粗；列为 `0–9`、`·` 与格底方块。每格计算 `key = 字形 | 行 | α（64 级）| 叠加（16 级）`，与上帧相同则跳过，不同才 `clearRect` 再 1–3 次 `drawImage`。稳态每帧只重画 1–3% 的格子。
8. **绘制预算**：每画 24 格检查一次耗时，超过 2.2 ms 就停下，剩余格子下一帧从中断处优先绘制（旋转游标）。入场再密集，单帧脚本也不超过 3 ms。

## 7. D3 页脚线框办公楼 `DecoFooterMark`

**概念**：页面的最后是一张轴测图。示例项目某综合办公楼从轴网开始，先画虚线地下室，再一层层升起裙楼、塔楼、屋顶机房；升起时，右侧的标高随楼顶读数，落成后留下 `+65.100`、`+14.400`、`±0.000` 三个标高符号，随后缓慢摆动。

### 7.1 模型（米，与 00 §8.1 对得上）

| 体块 | 平面 | 层数 × 层高 | 面积 |
|---|---|---|---|
| 地下室 | 68 × 50，`y −4.5 → 0`，虚线 | 1 | 3,400 m² |
| 裙楼 | 50 × 32，`y 0 → 14.4` | 3 × 4.8 | 4,800 m² |
| 塔楼 | 32 × 25（x −14…18，z −13.5…11.5），`y 14.4 → 65.1` | 13 × 3.9 | 10,400 m² |
| 屋顶机房 | 12 × 8，`y 65.1 → 69.6` | — | 不计 |

地上 4,800 + 10,400 = 15,200.00 m²，地下 3,400.00 m²，合计 18,600.00 m²（00 §8.1）。层数与层高是本章为画图补充的示意，页面上不写出来。轴网：裙楼开间 7 轴（1–7，间距 50/6 m）、进深 5 轴（A–E，8 m）。竖向分格：裙楼约 4.2 m，塔楼 4 m。

### 7.2 位置

| 方案 | 位置与尺寸 | 内容 |
|---|---|---|
| **建议（需 05 同意）** | 页脚末行：说明行之后单独一行，右对齐，440×200（≥ 1024），平板 360×160，手机不渲染；`margin-bottom: −32px` 贴住页脚底边 | 完整：轴号、虚线地下室、标高、实时标高 |
| 兼容 05 §5.3 原稿 | 角落位 240×120，距右下 0 | 紧凑：宽 < 320 时不画轴号与标高，整体不透明度 0.7；只在内容容器右缘 + 8px 以外作画，可用宽 < 64px 时不渲染。≥ 1024 时页边距 96px，可画出约 80px 宽的小楼 |

手机（≤ 767px）两种方案都不渲染（`display: none`，不分配画布）。

### 7.3 算法

1. **相机**：偏航 θ0 = 36°（右前方），俯仰 24°，距离 230 m，看向 `(0, 24, 0)`。相机位置 `C = T + D·(sinθ·cosφ, sinφ, cosθ·cosφ)`。投影：`x1 = px·cosθ − pz·sinθ; z1 = px·sinθ + pz·cosθ; y2 = py·cosφ − z1·sinφ; z2 = py·sinφ + z1·cosφ; sx = ox + f·x1/(−z2); sy = oy − f·y2/(−z2)`。
2. **取景**：把全部角点（含轴线端与地下室）在 θ0 ± (摆幅 + 指针偏量) 内取 7 个偏航角投影，取并集包围盒，按画布减内边距（14px）与标高列（66px）求 f 与偏移。缩放从此不变，摆动时不会越界。
3. **消隐**：每个体块是轴对齐长方体，侧面可见当且仅当相机在该面外侧（`C.x > x1` 可见 +x 面，依此类推），因此不需要排序。按“轴线 → 地下室虚线 → 裙楼 → 塔楼 → 机房”的顺序画，楼体面填不透明浅色（按面法线与光向 `(−.45, .8, .55)` 做 0.55–1 的明暗，在 `#e8eff8` 与白之间插值），后画的自然遮住先画的线。每个可见面依次画：填充 → 楼层线（α 0.3）→ 竖向分格（α 0.12）→ 轮廓（α 0.78）。
4. **轴号**：轴线为点划线（`9 3 2 3`，`#b9cbe3`），数字轴号在前端，字母轴号在左端。轴号属于标注，在楼体之后画；圆心落在楼体轮廓（各可见面路径的并集，`isPointInPath`）内的不画。
5. **搭建**：`H(t) = Σ_k ΔL_k × cubic.out(clamp((t − 0.95 − 0.12k)/0.34))`。17 步分别是 3 层裙楼、13 层塔楼、1 步机房，单调连续，约 3.2 s 搭完。各体块已建高度 = `clamp(H − y0, 0, h)`。正在升起的体块顶面描 1.5px accent、填 `#e3eeff`；右侧实时标高显示 `+18.300` 这样的读数。0–0.7 s 轴线从轴号端画出，0.4–1.0 s 地下室虚线画出。
6. **标高符号**：倒三角（5px）加 46px 引出线，读数写在线上（10px 等宽，`--text-muted`）。三角放在体块角点中屏幕 x 最大者的同一高度，用虚线连回角点。落成后按 0.08 s 间隔淡入。
7. **待机**（`live`，受 §3.3 调度）：`θ = θ0 + 11°·sin(2πs/26)·min(1, s/2) + 指针偏量`，s 为落成后的时间。指针在页脚内横移时，偏量按速率 2.5 逼近 ±9°。待机时 30 帧/秒重绘（转动很慢，减半帧率看不出差别）。

## 8. D4 尺寸线分隔 `DecoDimension`

**概念**：两节之间的接缝是一道尺寸标注。随着滚动，尺寸线从中点向两端拉开，数字从 0 数到容器的实测宽度（桌面 `1 248`，手机 `350`），也就是这条线真正量的长度。两端是 45° 起止符和尺寸界线，桌面在页边距里加上前后两节的轴号。

### 8.1 位置

- 只放在相邻两节背景色相同的接缝，每页最多 3 处；同一屏内不能同时出现 02 的 `.hero-dimline` 或 04 的 `.cap-dimline`。首页默认放在 `#roles → #problem`、`#workflow → #trust`、`#install → #faq` 三处。最终位置以 03–05 各节的背景色为准，在 `HomePage.vue` 中插入 `<DecoDimension from="3" to="4" />`。
- 尺寸：内容容器宽 × 56px（≤ 767px 为 44px）；尺寸线在 `y = 34`（手机 28）。端部轴号只在 ≥ 1024px 显示，圆心在容器外 34px。

### 8.2 算法

1. **SVG**：尺寸界线（`#c5d6ea`）、尺寸线（`#9db4d3`）、端部 45° 起止符（`--brand-navy`，1.5px，圆头）、栏刻度（`#a9bfdc`，画在 12/8/4 栏网格每个栏间距的两缘，即“连续尺寸”）、数字（12px 等宽 `--brand-navy`，千位空格）、端部轴号（r 9.5，白底 `#bfd0e6` 边）。宽度变化时按实测宽重建。
2. **进度**：ScrollTrigger `trigger: 根元素, start: 'top 92%', end: 'top 56%', scrub: SCRUB.soft`，`onUpdate` 把 `progress` 写给 `set(p)`。参考实现没有 GSAP，用等价的阻尼：`shown += (target − shown)·(1 − e^(−3dt/0.6))`。
3. **set(p)**：尺寸线 `x1 = W/2 − W·p/2`、`x2 = W/2 + W·p/2`（线性，00 §5.2 `EASE.linear`）；数字 `round(W·p)`，透明度 `min(1, 4p)`；栏刻度在线段覆盖到它时出现；`p ≥ 0.9` 时起止符与尺寸界线在剩余进度内伸出；`p ≥ 0.96` 时轴号淡入。同一 `p` 不重复写属性。
4. **不读布局**：文档纵坐标在重建时缓存，滚动帧内不调用 `getBoundingClientRect`。离开视口的分隔直接跳到滚动对应的状态，不做动画。

### 8.3 性能、降级、无障碍

- 实测滚动中 0.07–0.10 ms/帧，峰值 ≤ 0.7 ms（改为缓存纵坐标之前，读写交替造成强制布局，峰值 3.6 ms）。
- 减少动效：直接显示终态（满线、终值、端部全显），滚动无变化。无 JS：预渲染输出 1248 宽的终态 SVG（`viewBox` 按 1248），水合后按实测宽重建。打印：终态。
- `aria-hidden="true"`；数字不读出。

## 9. D5 404 图纸缺页 `DecoMissingSheet`

**概念**：您要的那一页不在图纸目录里。一张 A3 横幅底稿（420 × 297，装订边 25、其余 5，GB/T 50001）上，二层平面图画到接合线为止，旁注“接 A-404”，接合线另一侧是空白。修订云线圈出这片空白，索引符号指向“缺页：本页不在图纸目录中”，一枚“缺页”审核章落下，D1 的十字光标在空白处来回搜寻，读数是 `X ?  Y ?`。

### 9.1 位置与尺寸

- 06 §7.16 / 01 §12 的 404 深色区右侧（深色区由 D6 底纹铺底）。≥ 1024px：两栏 4fr / 7fr，SVG 宽 = 右栏宽（约 680–720），高按 424:301。768–1023px：文字在上，SVG 宽 100%（≤ 640）。
- ≤ 767px：默认按 01 §12 不显示。若 01 同意，用参考实现的裁切版：外层 `overflow: hidden`，SVG `width: 172%; margin-left: −70%`，只露出接合线、云线与审核章。见 §14 待定 1。

### 9.2 构建与技术

- 几何由纯函数 `missingSheetParts()` 生成，随机数用固定种子（Park–Miller），在 SSR 时输出静态 SVG，进入 `dist/404.html`，水合结果一致。约 190 个元素，24 KB，gzip 2.9 KB。404 页不加载 GSAP，也不加载画布组件。
- 线条颜色：图形 `#cfe0ff`，墙体用双描边（先画 2.6 宽浅色，再画 1.5 宽 `#082457`，得到双线墙，丁字接头自然融合），修订云线、索引与审核章用暖色 `#ffb48a`，十字用 `#8fc0ff`。
- 动画全用 CSS。基础样式就是终态，`@keyframes` 只描述“从哪里来”，所以减少动效、打印、无 JS 时直接是终帧：
  - 线：`pathLength="1"`、`stroke-dasharray: 1 1`，`@keyframes ms-draw { from { stroke-dashoffset: 1 } }`，时长与延迟写在 `style="--t; --d"`。
  - 点划线（轴线、接合线）不能用 `pathLength`（会缩放点划图案），只淡入。
  - 柱、轴号：`transform-box: fill-box` 后从 0.2 放大到 1。审核章：`scale(1.6) rotate(−6°) → none`，`cubic-bezier(.3, 1.6, .5, 1)`。
  - 十字光标：`@keyframes ms-roam` 在空白区 5 个点之间“移动 – 停留”，15 s 一圈，`var(--ease-in-out)`，4.4 s 后开始，无限循环。

### 9.4 暂停、降级、无障碍

- 页面隐藏或 SVG 离开视口时，给根元素加 `.paused`（`animation-play-state: paused`）。这一行判断是 404 页唯一的运行时脚本，约 0.3 KB。
- 减少动效、打印：`animation: none`，即终帧，十字停在初始点。
- 根元素 `aria-hidden="true"`、`focusable="false"`；页面的 H1、正文、两个按钮与 01 §12 的“请求地址”行都是 HTML，与装饰无关。

## 11. 验证方法与实测记录

**方法**（参考实现已按此验证，生产实现沿用）：

1. 以 `python3 -I -m http.server` 托管 `动效参考/`，用 Playwright 1.56.1 + Chromium 141.0.7390.37 headless（Linux 容器，无 GPU）分别打开各页。
2. 视口 1440×900（DPR 1）与 390×844（DPR 3、`isMobile`、`hasTouch`）。在 300 ms 与 2.5 s 截图，人工看图；收集 console 的 error/warning、`pageerror`、失败请求与外部请求。
3. 帧耗时：3 s 内 rAF 相邻回调间隔的均值与 p95；组件脚本耗时是组件在 `tick` 里用 `performance.now()` 量出的差（只算组件代码，不含栅格化与合成），由 `window.__deco.stats` 暴露。测量期间：D1 指针绕圈移动，D2 指针在面板内移动，D4 每 80 ms 滚动 60px，D3、D5 不操作。
4. 另测“从启动起算”的单帧峰值（含入场），DPR 1 与 DPR 2 各一次。
5. 离屏：页面加 4000px 底部留白、滚到底，1.2 s 内帧数增量；减少动效：`reducedMotion: 'reduce'` 下 1 s 内帧数；画布 DPR：`canvas.width / CSS 宽`。

|---|---|---|---|---|---|---|
| D1 | 16.67 / 16.7 ms | 0.19–0.23 / 0.6–1.0 ms | 0.8 / 1.1 ms | 0 | 0 | 静态帧，0 帧；静态层画布 2×，动态层释放 |

## 12. Three.js 决策

**不引入 Three.js；全站 WebGL 场景数为 0**（00 §5.1 允许的一个名额不用）。

- 唯一可能用到 3D 的是 D3：3 个长方体、约 160 条线段、每帧约 320 个投影点。Canvas2D 加二十余行投影与消隐代码就能完成，实测 0.23 ms/帧，组件约 5 KB gzip。Three.js（`WebGLRenderer` 与核心类难以摇树）约 150 KB gzip 以上，是 D3 的 30 倍左右，还会占掉 00 §9 给 3D 的整块预算。
- 细线是这张图的主体。WebGL 的 `LineBasicMaterial` 在多数平台只能画 1 设备像素宽的线（`linewidth` 无效），虚线要 `LineDashedMaterial` 加 `computeLineDistances`，消隐要 `polygonOffset`，轴号与标高文字还要 `CSS2DRenderer` 或精灵；Canvas2D 原生支持 `setLineDash`、`fillText` 与亚像素抗锯齿，图更清楚。
- WebGL 还有上下文创建的一次性开销、上下文丢失处理、显存与移动端功耗的代价，换来的只是在这张小图上看不出差别的透视。
- 以后若真有需要 GPU 的场景（例如上万个粒子），再按 00 §9 的 170 KB 上限单独评估，且必须懒加载、全站只此一个。
