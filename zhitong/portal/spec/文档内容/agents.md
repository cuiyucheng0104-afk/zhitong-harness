一个项目的工作往往有很多步：盘点资料、核对、算指标、查异常、写报告。智通数工AI 可以在一次对话里按顺序做完，也可以先给您看计划、把独立的活分给子智能体并行去做、在后台跑长时间的任务，或者朝一个目标连续推进。本页说明这些能力在本产品里**已经启用**的部分，以及您怎样触发、怎样在界面上看到它们。

无论用哪种方式，规则不变：金额由脚本计算，结果需要您确认，需要拍板的事由您决定。

## 一览

| 能力 | 适合 | 您怎么触发 | 界面上看到 |
|---|---|---|---|
| [计划模式](/docs/agents/#计划模式先看计划再动手) | 多步、影响大的工作，想先看方案 | 输入 `/plan` | 输入框旁出现"计划"标记；计划提交后出现"计划待审"卡片 |
| [任务清单](/docs/agents/#任务清单看它做到哪一步) | 任何多步工作 | 不用触发，它自己维护 | 工作步骤里的"更新了计划"，显示已完成数 / 总数 |
| [子智能体](/docs/agents/#子智能体把独立的活分出去) | 几件互不依赖的活，比如分头读几份资料 | 它自己判断，或您说"分给子智能体去做" | 工作步骤"正在协调子智能体"；页头"N 个子智能体" |
| [工作流](/docs/agents/#工作流一次编排多个子智能体) | 很多份同类工作要批量分派 | 您明确说"用工作流" | 对话里的工作流节点，按阶段列出成员与状态 |
| [目标](/docs/agents/#目标朝一个结果连续推进) | 要连续推进很多轮才能完成的工作 | 输入 `/goal <目标>` | 输入框上方的目标条 |
| [后台任务](/docs/agents/#后台任务长时间运行不挡对话) | 耗时长的命令、子智能体或工作流 | 它自己判断，或您说"放到后台跑" | 页头"N 个后台任务运行中" |
| [定时提醒](/docs/agents/#定时提醒到点在原对话里继续) | 到某个时间回来做一件事 | 您说"每周一 9 点提醒我…" | 侧栏"自动化任务"页面；对话页头的提醒入口 |
| [上下文压缩](/docs/agents/#上下文压缩长对话不中断) | 很长的对话 | 自动；也可输入 `/compact` | "上下文已压缩" |

## 计划模式：先看计划再动手

在计划模式里，它先读资料、查目录，把完整的计划写出来交给您审，您同意后才开始做。

::: steps
1. 在输入框输入 `/plan`，或 `/plan` 后面直接跟任务，例如 `/plan 2026-007 从资料盘点做到核对和指标，先给我计划`。输入框旁出现"计划"标记，表示计划模式已开启。
2. 它开始查看项目说明和目录，然后提交计划。对话里出现"计划待审"卡片：计划标题、两行摘要，以及"查看全文"链接；计划全文同时在右侧边栏打开。
3. 审阅后二选一：
   - 点"同意执行"：离开计划模式，开始按计划做。
   - 点"要求修改"，在输入框写下意见发送：它修改计划后再次提交。
4. 不想等计划了，点输入框旁的"计划"标记，或输入 `/plan off`，直接离开计划模式。
:::

- 审过的计划之后还能在那一轮对话末尾的计划卡片里重新打开。
- 计划模式是对它的**工作方式引导，不是权限限制**：在计划阶段它被要求只查看、不修改，但需要批准的操作仍然会请您批准（见[基本用法](/docs/basics/#需要您批准时越权执行)）。
- 计划的格式来自通用的规划引导，可能出现"成功标准""假设""验收"等小节，按工作内容理解即可。
- 在计划模式里，您回答它的确认提问不等于同意计划；只有点"同意执行"才会开始执行。

::: utterances
- /plan 2026-007 结算审核：从资料盘点做到核对、指标，最后汇总待确认事项，先给我计划
- /plan 2026-007 要出结算审核报告初稿，先列出要用的资料和章节安排
:::

## 任务清单：看它做到哪一步

做多步工作时，它会维护一份任务清单：把工作拆成具体任务，标出正在做的，做完一项勾掉一项。

- 对话里出现"正在更新计划"/"更新了计划"的工作步骤，显示已完成数 / 总数和当前在做的任务，展开可以看全部任务和状态（待办、进行中、已完成）。
- 可以有几项同时在进行，比如几个子智能体在并行工作时。
- 清单跟着这次会话保存，重新打开会话后仍在。
- 您不能直接编辑清单。要增删任务或调整顺序，在对话里告诉它。

## 子智能体：把独立的活分出去

子智能体是它临时派出的"助手"：在独立的上下文里完成一件明确的事，把结果交回主对话。适合几件**互不依赖**的活同时做，比如分别读几份很长的资料、分别核对几个单体。

**怎么触发**：多数时候它自己判断；您也可以直接说"分给两个子智能体去做"。

**界面上**：

- 工作步骤显示"正在协调子智能体"。
- 会话页头出现"N 个子智能体"（有在运行的显示"N 个子智能体，正在运行"），点开是子智能体列表，可以"在侧边栏打开"查看每个子智能体的完整对话。
- 每个子智能体标有状态（正在运行、已完成、当前未运行）和类型："可继续"的可以接着给它发消息、也可以停止；"一次性"的只能查看记录。
- 子智能体完成时，主对话会收到通知（显示"子任务状态更新"），它读取结果后继续。

**规则与限制**：

| 项 | 说明 |
|---|---|
| 两种派法 | 全新子智能体（不带当前对话内容，只拿到交代的任务）；或"分叉"子智能体（带着当前对话已完成的内容） |
| 模型 | 默认沿用当前对话的模型 |
| 层级 | 默认只有主对话能派子智能体，子智能体不能再往下派。可在设置的"子智能体"页面调整最大递归深度和并行数量上限 |
| 提问 | 子智能体**不能**向您发起确认提问；需要您决定的事，它会写进结果，由主对话来问您 |
| 定时提醒 | 子智能体不能创建提醒 |
| 结果 | 子智能体的结论回到主对话后，仍按同样的规则转述：金额以脚本结果为准，引用要有出处 |

::: tip 让子智能体只写工作目录
子智能体和主对话使用同样的工具，也能推送文件到桶。如果不希望它们直接改桶里的文件，交代任务时说清楚："只把结果写到 `工作/` 下，不要推回桶，由你汇总后再推。"
:::

## 工作流：一次编排多个子智能体

工作流是一段由它编写的编排脚本，按阶段把一批工作分派给多个子智能体，等全部完成后返回汇总结果。它只在您**明确要求**"用工作流"或要做大批量分派时使用；一两件事直接用子智能体。

::: steps
1. 您说明要批量做的事，并明确说"用工作流"。
2. 对话里出现一个工作流节点：展开可以看到各阶段，阶段下是成员（子智能体），每个成员标有状态：运行中、已完成、失败、已取消、已中断。运行中的成员可以点开查看。
3. 默认情况下，它会等工作流全部结束再继续；也可以让它放到后台跑（见下一节），先做别的。
4. 全部完成后，它拿到汇总结果并转述。取消或出错时，它报告失败，不会把一半的结果当作完成。
:::

::: utterances
- 用工作流：2026-007 资料/6 其他/ 下的扫描件，每份派一个子智能体看图，摘出签证编号、日期和涉及部位，汇总成一张表写到工作目录
:::

## 目标：朝一个结果连续推进

设定目标后，它每做完一轮，只要目标还没完成、也没有受阻，就自动开始下一轮，直到完成。适合"把报告每一章都写完"这类需要很多轮的工作。

::: steps
1. 在输入框输入 `/goal`，后面写目标，例如 `/goal 写完 2026-007 结算审核报告初稿的全部章节，每章通过数字核对后再写下一章`。
2. 输入框上方出现目标条，显示"进行中的目标"。之后每一轮开始时，对话里标注"继续执行目标"。
3. 目标条上可以"暂停目标""恢复目标""编辑目标""清除目标"。也可以输入 `/goal pause`、`/goal resume`、`/goal edit <新目标>`、`/goal clear`；只输入 `/goal` 查看当前状态和已用轮数。
4. 它判断目标完成时会标记完成；遇到无法继续的情况，目标条显示"受阻的目标"和原因。
:::

- 每个会话同时只有一个目标。
- 默认最多连续 256 轮，用完会停下并标记受阻。每一轮都会产生模型调用费用，不需要时及时暂停或清除。
- 它需要您确认时，确认提问照常出现，回答之前不会继续。
- 应用重启或重新打开会话后，目标**不会自动继续**，需要您输入 `/goal resume`。
- 目标要写清"做到什么程度算完成"，否则它难以判断何时停。

## 后台任务：长时间运行不挡对话

耗时长的命令、子智能体或工作流可以在后台运行，它同时继续和您对话。

- 会话页头显示"N 个后台任务运行中"。点开是任务列表：进行中的任务显示已运行时长，可以展开看实时输出；已结束的任务折叠在"已结束 N"下面。
- 停止某个任务：点它的停止按钮，再点一次"确认停止"。
- 任务结束时它会收到通知（显示"后台任务状态更新"），并读取结果；不需要您去催。
- 状态：运行中、正在停止、已完成、已取消、已失败。

::: utterances
- 这个工作流放到后台跑，跑完告诉我
- 后台还有什么任务在跑？
:::

## 定时提醒：到点在原对话里继续

您可以让它在某个时间、或按周期，回到这个对话做一件事。

::: utterances
- 每周一上午 9 点提醒我看 2026-007 的待确认清单还有几项没处理
- 明天下午 3 点提醒我把 2026-007 的核对结果推回桶
:::

- 到点时，提醒作为一条消息出现在**原来的对话**里（显示"自动化任务"），它照这条消息去做。它不是邮件、短信或手机推送。
- 侧栏的"自动化任务"页面列出所有提醒，可以查看、修改名称、内容和时间，或删除；对话页头也有本对话提醒的入口。
- 只有应用在运行时才会按时投递。应用关闭期间错过的：一次性提醒在下次启动后补发；重复提醒只补发最近错过的一次。
- 支持一次性、固定间隔（至少一分钟）、每天、每周和自定义周期。说时间时带上时区更准确，例如"北京时间"。
- 投递记录只表示消息已送到对话，不表示它已经做完。

## 上下文压缩：长对话不中断

对话接近模型能处理的长度上限时，它会把较早的内容压缩成一段摘要、保留最近的对话，然后继续。对话里显示"上下文已压缩"，以及"已压缩 N 条历史记录（约 M tokens）"，点击可以查看压缩摘要。

- 您也可以随时输入 `/compact` 手动压缩。它正在工作时压缩暂不可用。
- 压缩后，较早内容的细节只剩摘要。产品的做法是把关键结论写进文件（项目说明的工作记录、`待确认清单.md`、工作底稿），所以压缩不会丢掉项目上的结论。

## 一个完整的例子：2026-007 结算审核

下面是在示例项目 2026-007-滨江综合办公楼上的一次工作。所有数字为示例。

::: steps
1. **出计划**。您输入：`/plan 2026-007 结算审核：从资料盘点做到核对、指标，最后汇总待确认事项，先给我计划`。它读项目说明、列出 `资料/` 目录后提交计划，"计划待审"卡片里列出：资料盘点 → 送审审定核对 → 造价指标 → 汇总待确认事项。您点"同意执行"。
2. **任务清单出现**。工作步骤"更新了计划"显示 0/4，当前任务"资料盘点"。
3. **盘点与核对**。它按项目说明找到 `资料/4 结算资料/送审计价表.xlsx` 和 `审定计价表.xlsx`，运行核对脚本，底稿写到 `工作/2026-10-19-核对/`。汇报：送审 30,530,406.80 元，审定 29,623,713.84 元，核减 906,692.96 元，核减率 2.97%；按章汇总里门窗工程核增 32,612.74 元（送审 2,915,613.80，审定 2,948,226.54）。全部标注需人工确认。
4. **分头查依据**。您说："门窗工程为什么核增？分两个子智能体去查：一个读 `资料/5 变更资料/签证单汇总.xlsx`，一个读 `资料/6 其他/施工日志.docx`，找和门窗有关的变更与签证，带出处回来，只写工作目录，不要推回桶。"页头出现"2 个子智能体，正在运行"。
5. **汇总**。两个子智能体完成后，它把找到的条目合并成一份清单，每条带出处（格式如〔资料/5 变更资料/签证单汇总.xlsx 工作表!R行号〕），写到 `工作/2026-10-19-门窗核增依据/`；没有找到依据的部分如实说明。
6. **待确认事项**。它把门窗核增依据是否充分、两份资料是否有矛盾等事项写进 `待确认清单.md`，任务清单显示 4/4。
:::

::: confirm
- 核增核减金额以 `核对结果.xlsx` 为准，对照原表复核。
- 子智能体找到的签证、变更条目只是线索：逐条打开原件核对出处，再判断能否支持核增。
- 是否推回桶、何时推回，由您决定。
:::

## 什么时候不必用

- 一问一答、读一份文件、跑一次核对：直接说，不需要计划模式或子智能体。
- 一两件分派：用子智能体，不用工作流。
- 一轮就能做完的事：不要设目标。
- 每多一个子智能体、每多一轮目标，都会多一份模型调用费用。

## 常见问题

### 子智能体会不会改坏桶里的文件？

子智能体与主对话的工具相同，推送文件时同样会回读校验，覆盖时桶里保留旧版本。不希望它们推送时，在交代任务时说明"只写工作目录、不要推回桶"。

### 想让它停下来怎么办？

点输入框的"停止生成"停止当前这一轮；后台任务在任务列表里停止；可继续的子智能体在子智能体列表里停止；目标用"暂停目标"或 `/goal pause`。

### 计划模式里它会不会直接动手？

它被要求在计划阶段只查看、不修改，等您点"同意执行"再做。这是工作方式的引导；需要批准的操作仍会请您批准。

### 关掉应用后，目标和提醒还在吗？

都在。目标保存在会话里，但重新打开后不会自动继续，需要 `/goal resume`。提醒保存在本机，应用重新运行后继续按时投递，错过的按上面"定时提醒"的规则补发。
