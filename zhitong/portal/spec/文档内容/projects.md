公司的项目资料、成果和知识库都放在公司自己的火山引擎对象存储（TOS）存储桶里，按统一规范组织。接手项目的同事先读项目说明，就能找到合同、招标文件、送审和审定计价表、设计说明和图纸；智通数工AI 也按同样的规范找文件。

## 存储桶的总体结构

所有路径都相对"公司前缀"（配置包里设定的桶内目录）。对话里、文档里写的 `项目/…`、`知识库/…` 都是指这个前缀下面。

::: filetree
```text
<公司前缀>/
  项目/
    <项目编号>-<工程名>/   # 每个项目一个目录，见下节
  知识库/
    规范/                  # 每个子目录有一份 README.md 说明内容与来源
    定额/
    费率/
    模板/
    公司经验/              # 工作中发现的口径与经验
  案例索引.md              # 每个项目一行的汇总表
```
:::

不建数据库，也不建检索索引。它找文件的顺序是：先读项目说明，再按需拉取具体文件。

## 项目目录

::: filetree 示例项目 2026-007
```text
项目/2026-007-某综合办公楼/
  项目说明.md                         # 入口：基本信息、关键文件指引、已出成果
  资料/                               # 客户原件
    1 合同及协议/施工合同及补充协议.docx
    2 招标资料/招标文件.pdf · 工程量清单.xlsx
    3 竣工资料/竣工图/竣工图总说明.pdf
    4 结算资料/送审计价表.xlsx · 审定计价表.xlsx · 结算送审书.pdf
    5 变更资料/签证单汇总.xlsx
    6 其他/施工日志.docx · 扫描件0001.pdf · 扫描件0001.pdf.ocr.txt
  图纸/
    A-02 二层平面图.dwg
    .cache/                           # 看图时生成的转换缓存
  工作/
    2026-10-19-核对/                  # 中间产物：<日期>-<任务>
      result.json · 核对结果.xlsx · 待确认清单.md
  成果/                               # 正式成果
```
:::

| 目录 | 放什么 | 谁来写 |
|---|---|---|
| `项目说明.md` | 项目入口文件，见下文 | 开项目时生成；归档时更新；字段可由您改 |
| `资料/` | 客户提供的原件。扫描件的识别文本以 `<原件名>.ocr.txt` 与原件放在一起 | 您或服务方整理 |
| `图纸/` | DWG、DXF、图纸 PDF。看图产生的缓存（DXF、图框图片）在 `图纸/.cache/` | 您；缓存由看图工具生成 |
| `工作/<日期>-<任务>/` | 中间产物：核对、指标、投控、清单的结果文件与工作底稿，`待确认清单.md` | 它在执行任务时写入。日期格式 `YYYY-MM-DD`，同一天同类任务再做一次加 `-2` |
| `成果/` | 报告、审定单、清单、概算等正式成果 | 它在您确认后写入 |

扫描件优先读旁边的 `.ocr.txt` 识别文本，没有时才看图。识别文本里的金额和编号要对照原件核对。

## 项目编号

格式 `YYYY-NNN`：建项目的年份 + 当年三位流水号，例如 `2026-007`。

- 流水号取案例索引与 `项目/` 目录里当年最大值加一；中间空号不补；每年从 001 重新开始。
- 目录名为 `<编号>-<工程名>`，工程名去掉空格和 `/ \ : * ? " < > |` 这些字符。
- 客户自己的合同号或内部编号（如示例中的合同号 HT-DEMO-07）写在项目说明的"别名"里，不进目录名。

新开项目时，它先算出编号与目录名请您确认，然后建立项目说明、在案例索引里追加一行，并**立即**推回桶，编号在推送后才算占住。编号分配没有加锁：两个人几乎同时开项目时，后推送的一方会收到"别人刚改过案例索引"的提示，它会重新拉取案例索引、删掉本机新建的目录、重新分配编号。详见[开项目与资料盘点](/docs/features/project/)。

## 项目说明.md

项目说明是它开项目时第一个读的文件，也是接手同事的入口。文件开头 `---` 之间是字段区，一行一个"字段: 值"，脚本读写这部分；正文各节给人和它看。

### 字段

| 字段 | 填什么 | 示例（2026-007） |
|---|---|---|
| 项目编号 | `YYYY-NNN` | 2026-007 |
| 工程名称 | 工程名 | 某综合办公楼 |
| 咨询类型 | 全过程造价咨询 / 结算审核 / 招标控制价编制 | 结算审核 |
| 阶段 | 概算 / 招标控制价 / 施工过程 / 结算 / 审定 | 审定 |
| 业态 | 可选 | 办公 |
| 规模 | 可选 | 建筑面积 18,600.00 m² |
| 别名 | 客户合同号、内部编号，可多个 | HT-DEMO-07 |
| 旧系统项目ID | 从旧系统迁移来的项目才有 | （空） |
| 状态 | 进行中 / 已归档等 | 进行中 |
| 建立日期 | `YYYY-MM-DD` | 2026-10-19 |

咨询类型或阶段写着"待确认"时，项目说明被视为不完整：它会先问您，把字段补上，再做后面的工作；归档时这也是阻断项。

### 正文各节

| 小节 | 内容 | 谁维护 |
|---|---|---|
| 基本信息 | 与字段区一致的表格 | 生成时写入 |
| 关键文件指引 | 合同、招标文件 / 招标控制价、工程量清单、送审计价表、审定计价表、设计说明、图纸在项目内的相对路径 | 核对过的路径才写；按文件名推断的候选标"待确认"，打开核对后去掉 |
| 资料盘点 | 盘点日期、依据的咨询类型与阶段、缺件、待确认的资料 | 资料盘点时写入 |
| 已出成果 | `成果/` 下的文件，一行一个 | 归档时登记 |
| 工作记录 | 每次任务一行：日期、做了什么、产物位置、待确认事项 | 每次任务后追加 |

没有项目说明的目录（迁移来的或手建的），它会按目录结构生成草稿：从目录名取编号和工程名，按文件名填"关键文件指引"的候选。草稿不会覆盖已有的项目说明。

## 案例索引.md

案例索引在公司前缀根目录，每个项目一行，是跨项目查案例、对标指标的汇总表。查别的项目时，它读这份索引，再进对应项目，不需要数据库。

| 列 | 内容 | 示例（2026-007 归档后，示例数据） |
|---|---|---|
| 编号 | 项目编号 | 2026-007 |
| 工程名 | 工程名 | 某综合办公楼 |
| 业态 | | 办公 |
| 规模 | | 建筑面积 18,600.00 m² |
| 咨询类型 | | 结算审核 |
| 关键指标 | 只写成果里已算好的数，并写明口径 | 土建单方造价 1,592.67 元/m²（审定，按建筑面积） |
| 成果链接 | 项目成果目录 | `项目/2026-007-某综合办公楼/成果/` |
| 状态 | 进行中 / 已归档等 | 已归档 |

- 开项目时追加本项目一行；归档时更新"关键指标""成果链接""状态"。
- 只改自己项目那一行，不重排、不删别人的行。
- "关键指标"不现场计算，只抄成果里已有的数。

::: note 案例索引的列
产品规格书写的是前 7 列，当前模板多一列"状态"，是否保留尚待产品负责人确认（`zhitong/STATUS.md`）。如果贵司的案例索引没有这一列，以贵司文件为准。
:::

## 知识库目录

`知识库/` 对所有项目可见，分为规范、定额、费率、模板、公司经验五个子目录，每个子目录有一份 `README.md` 说明内容与来源。工作中发现的口径与经验，它会写进 `公司经验/`，每条记录来源和日期。详见[企业知识库](/docs/features/knowledge/)。

## 本机缓存

它不把整个桶下载下来，只把用到的文件拉到您电脑上的缓存目录处理。

| 项 | 说明 |
|---|---|
| 位置 | `~/zhitong`（Windows `%USERPROFILE%\zhitong`），目录结构与公司前缀以下完全一致 |
| 容量 | 默认上限 20 GiB。超出时按最近使用时间淘汰本机未修改过的文件；本机改过、还没推回桶的文件不会被淘汰 |
| 去重 | 桶里的文件与本机副本一致时不重复下载 |
| 图纸 | 拉取整个目录时默认跳过 `.dwg .dxf .rvt .skp .3dm .ifc .nwd .zip .rar .7z`；需要看哪张图时单独拉取 |
| 单次上限 | 一次拉取最多 200 个文件；单个文件上传最大 5 GiB |

它能告诉您某个文件的本机副本状态：

| 状态 | 含义 |
|---|---|
| current | 本机副本与桶里一致 |
| stale | 桶里已更新，本机副本是旧的 |
| modified | 本机改过，还没推回桶 |
| untracked | 本机有同名文件，但不是从桶里拉下来的 |
| absent | 本机没有 |

本机改过、还没推回桶的文件，拉取时**不会被覆盖**（结果显示冲突），除非您确认放弃本机修改。

::: note Windows 文件名
文件名里有 `< > : " | ? *`、以点或空格结尾、或是 Windows 保留名（如 `CON`）时，在 Windows 上无法保存，拉取会直接报错，不会自动改名。请在桶里改名，或在 Mac 上处理。
:::

## 多人同时使用

同一个桶由多位同事共用。桶开启了版本控制，**不做文件锁**：任何人推送都会成功，被覆盖的旧版本保留在版本历史里。

它推送文件后会回读校验，并告诉您两件事：

- **覆盖了旧版本**：结果里写明被覆盖版本的时间，可以从版本历史恢复。
- **别人在您拉取之后改过这个文件**：说明这次推送覆盖了同事的修改。它会明确告诉您，不会悄悄带过。

建议的协作规则：

1. 一个项目的一项任务，同一时间由一个人做。
2. 开始前让它拉取最新的项目说明和要用的文件；完成后及时推回桶。
3. 看到"别人改过"的提示，先停下与同事确认，再决定保留哪一版。
4. 案例索引只改自己项目的行。
5. 恢复旧版本：由贵司管理员在火山引擎控制台的版本管理中操作。

## 文件命名与路径

- 中文和空格出现在路径里都是正常的。
- 对话里提到的路径都是项目内相对路径，用 `/` 分隔，如 `资料/4 结算资料/送审计价表.xlsx`。
- 工作目录按 `YYYY-MM-DD-任务` 命名；不按此命名，归档检查时会提醒。
- 文件名和目录名前面的一长串数字是存储编号，不代表资料属性。
