## 一句话

比对送审与审定计价表，脚本算出核减额、核减率、按章汇总与量差价差，底稿存入工作目录，由您复核。

## 适用场景

- 结算审核：比对施工单位的结算送审计价表与审核后的审定计价表。
- 进度款审核：比对某一期的报审表与审核表，可指定按本期、累计或合同价取数。
- 审定单复核：您拿到一份审核汇总表或审定单，想确认它与明细计价表是否对得上。
- 定位问题行：只想知道哪些清单项被调整、哪些只在送审里出现、哪些是审定新增。

不适用：

- 广联达等造价软件的原生工程文件（`.gbq*`、`.gtj`、`.gcl`）不能直接读，需要先从软件里导出 Excel。
- 旧版 `.xls` 不在本机转换，需要先另存为 `.xlsx`。

## 您可以这样说

::: utterances
- 核对一下送审和审定计价表。
- 把 2026-007 的送审和审定比一下，看核减了多少，哪几章减得最多。
- 这是第 5 期进度款，按本期金额比，不要比累计。
- 混凝土这章为什么核减这么多？把核减最大的 10 行列出来，带原表行号。
- 列一下只在送审里有、审定里没有的清单项。
- 资料里有好几份 Excel，你先看看哪份是送审、哪份是审定。
:::

## 需要准备的资料

| 资料 | 要求 | 放在哪里 |
|---|---|---|
| 送审计价表 | `.xlsx` 或 `.xlsm`；分部分项工程量清单与计价表（表头有项目编码、项目名称、工程量、综合单价、合价），或审核汇总表（表头有报审、审核、核减金额） | 项目的 `资料/`，通常在 `资料/4 结算资料/` |
| 审定计价表 | 同上 | 同上 |
| 项目说明 | 项目根目录的 `项目说明.md`；其中「关键文件指引」写明两张表的位置时，助手直接使用，不再询问 | 项目根目录 |

文件数量与大小：一次核对送检的文件合计不超过 60 份、300 MB。单张工作表超过 8,000 行时只取前 8,000 行，并给出告警 `sheet_truncated`。

::: tip
一份工作簿里可以有多张清单表（分部分项、施工技术措施等），脚本会逐张识别；封面、编制说明、工日 / 台班 / 材料一览表等非清单表按标题跳过，并以 `info` 级告警 `sheets_skipped_by_title` 说明。
:::

## 它会怎么做

::: steps
1. **读项目说明**（`read 项目说明.md`）。按「关键文件指引」找到「送审计价表」「审定计价表」。
2. **指引里没有，或同一角色有多份候选时，先预检**（`probe.py probe`）。预检只判断文件是不是计价表，不读金额，每份文件给一个标签：
   - `costsheet`：认出了清单表头，是计价表；
   - `other`：读过了，没有清单表头；
   - `unknown`：没读或没读完，附原因（例如「旧格式 .xls，未预检；请用 Excel/WPS 另存为 .xlsx」）。

   助手把候选文件名、标签和表头里出现的期次（如本期、累计、合同）列给您，用选项卡请您指定哪份是送审、哪份是审定。助手不按文件名猜。
3. **拉取文件**（`tos_pull`）。文件在公司的火山引擎对象存储（TOS）里时，先拉到本机缓存，再用本机路径运行脚本。
4. **运行核对**（`reconcile.py run`）。工作目录是 `工作/<日期>-核对/`，同一天再做一次用 `工作/<日期>-核对-2/`。对比口径默认 `auto`：表里有本期列就比本期，否则比合价。
5. **读结果**。先看状态与告警，再看汇总与按章数据。逐行结果可能上千行，助手不会整份读进对话，而是按状态过滤，再按核减额绝对值取前 20 行。
6. **汇报**，顺序固定：结论一句 → 按章（核减额绝对值最大的 3–5 章）→ 主要调整项（带送审位置、审定位置）→ 量差与价差 → 状态与告警。
7. **写待确认清单**，把需要您拍板的事项写进 `待确认清单.md`，每条注明来源（文件、表、行或告警码）。
8. **推回桶**（`tos_push`），整个 `工作/<日期>-核对/` 目录推回同一项目。
:::

## 结果怎么读

### 汇总字段

| 字段 | 含义 |
|---|---|
| `a_total` / `b_total` | 送审合计 / 审定合计 |
| `adjust_amount` | 核减额，送审 − 审定；正数为审减，负数为审增 |
| `adjust_rate` | 核减率 = 核减额 ÷ 送审合计，页面显示两位小数 |
| `count_same` / `count_changed` / `count_only_a` / `count_only_b` / `count_uncertain` | 一致 / 调整 / 仅送审 / 仅审定 / 待核实的行数 |
| `diff_by_qty` / `diff_by_price` | 量差合计 / 价差合计 |
| `basis_label` | 两侧实际取数的口径，例如「不分期」「本期·送审」 |

### 逐行状态

| 状态 | 含义 | 您通常要做的 |
|---|---|---|
| 一致 | 两侧合价相差不超过 1 分；差 1 分时「标记」列写「舍入差 ±0.01」 | 一般不用看 |
| 调整 | 两侧都有这一行，金额不同 | 看量差、价差，核对调整依据 |
| 仅送审 | 审定侧没对上 | 确认是审减删项，还是写法不同没对上 |
| 仅审定 | 送审侧没对上 | 确认是审增新增，还是写法不同没对上 |
| 待核实 | 某一侧这一行存在，但合价没取到；不按 0 计算差额 | 打开原表核对 |

「匹配依据」列说明这一行是怎么对上的：`编码`（按项目编码）或 `名称特征`（编码对不上时按名称和特征）。

### 量差与价差

- 量差 =（送审量 − 审定量）× 审定单价。
- 价差 =（送审单价 − 审定单价）× 送审量。
- 两侧都满足「量×价=合价」时，一行的量差 + 价差 = 这一行的核减额。
- 汇总里的量差、价差只统计两侧量、价都取到的匹配行。仅送审、仅审定行没有另一侧的量价，计算错误行的算术差也不在其中，待核实行不参与归因，所以汇总的量差与价差相加一般不等于核减额。

示例中，核减额 906,692.96 元的构成：

| 部分 | 金额（元） |
|---|---|
| 匹配行量差 | 612,418.27 |
| 匹配行价差 | 147,749.55 |
| 仅送审 23 行合价 | +186,342.50 |
| 仅审定 9 行合价 | −41,817.36 |
| 送审计算错误 1 行差额 | +2,000.00 |
| 合计 | 906,692.96 |

### 标记列

「送审计算错误」「审定计算错误」表示这一侧 |量×价 − 合价| 超过 1 元与合价 0.5% 中较大的一个。进度款表里合同量 × 单价 ≠ 本期产值是正常现象，这种情况不标。

### 状态

| 状态 | 助手会怎么说 |
|---|---|
| `ok` 完成 | 给出结论 |
| `partial` 部分完成 | 说明哪些表或文件没算进去，结论不完整 |
| `insufficient` 资料不足 | 不给任何金额结论，转述原因和下一步 |

告警码的完整说明见 [结果状态与告警](/docs/results/)。

## 需要您确认的事项

::: confirm
脚本结果是工作底稿，不是审定结论。所有金额、数量都需要您复核。

1. **文件选得对不对**。尤其是出现以下告警时，多半是文件或口径选错了，助手会先问您，再汇报结论：
   - `amounts_identical_suspect`：两侧金额疑似取成同一列；
   - `all_rows_identical`：每一行都一致、核减额为 0；
   - `same_file_sheets_excluded`：送审、审定选了同一份文件，而且没有两组金额列。
2. **对比口径**。进度款表先用 `auto`；结果提示口径问题时，按提示改为本期、累计或合同价。
3. **待核实行**。合价没取到的行不按 0 计算，需要您打开原表确认。
4. **仅送审、仅审定行**。确认是删项 / 新增，还是编码、名称写法不同没对上。
5. **计算错误行**。标了「送审计算错误」「审定计算错误」的行，差额可能来自算术错误。
6. **error 级告警**。每条都意味着有内容没算进去或算不准，例如 `sheet_total_mismatch`（明细之和与合计行偏差超过 0.5%）、`measure_sheet_unreconciled`（技术措施表对不上，整张未计入）。
:::

## 限制与注意

- **只读 `.xlsx` / `.xlsm`**。`.xls` 会得到 `insufficient`（`xls_unsupported`），请用 Excel 或 WPS 另存为 `.xlsx`。
- **不读广联达原生工程文件**（`.gbq*`、`.gtj`、`.gcl`），请先在广联达里导出 Excel。
- **送检上限**：每次合计 60 份、300 MB，超过时脚本报错并提示分批运行。预检另有限制：一次最多 60 份，单份超过 64 MB 不预检，总时限 8 秒，到时未轮到的文件标为「预检时间用完」。
- **单表 8,000 行**：超过的部分不读，并给出 `sheet_truncated` 告警。
- **模型不算钱**：助手不对金额做加减乘除，也不换算比例；脚本结果里没有的数，助手会说没有。
- **验证范围**：本版核对脚本用旧系统的金标数据与多种版式的合成表格测试通过，尚未在真实的广联达导出文件上完成端到端验收。遇到识别不了的版式，请把文件与告警一起反馈给管理员。
- **告警提示里的旧界面说法**：部分告警的处理建议沿用旧网页的说法，例如「对比口径」指本页的对比口径（`--basis`），「重新选择 / 分别选择文件」指换一份送审或审定文件。您在对话里直接说要换哪份、按什么口径即可。
- **正式成果**：审定单、审核报告进入 `成果/` 由 [报告撰写](/docs/features/report/) 负责，核对只写 `工作/`。

## 常见问题

### 为什么核减率是 2.97%，我手算是 2.9698%？

核减率字段保留四位小数（0.0297），页面按两位百分数显示。需要更多位数时，请以送审合计和核减额自行复核。

### 结果里「仅送审」有 23 行，是不是都被审减删掉了？

不一定。「仅送审」只说明审定侧没有对上这一行。可能是删项，也可能是两边编码不同、名称写法不同。请看「送审位置」打开原表，必要时对照审定表同一部位。

### 提示 `basis_not_found` 是什么意思？

您指定的口径（例如本期）在表头里找不到对应金额列。请改回 `auto`，或从结果 `data.detail.basis_available` 列出的口径里选一个。直接对助手说"改成按累计比"即可。

### 同一份审核对比表里同时有送审和审定两组金额列，可以只给一份文件吗？

可以。两侧选同一份文件、表头有两组金额列时，脚本按两组列分别取数，并以 `same_file_two_sides`（info）说明这是正确用法。如果表里只有一组金额列，同一份文件放两侧必然全部一致，脚本会剔除这些表并给出 error 级告警。

### 送审有 6 号楼、7 号楼两份文件，审定是一份，能核对吗？

本能力一次比对一份送审表和一份审定表。多份文件请分楼栋分别核对，或先在 Excel 里合并成一份工作簿。

### 同一天想换个口径再跑一次，会覆盖上一次的结果吗？

不会。同一天第二次核对写到 `工作/<日期>-核对-2/`，两次结果都保留。
