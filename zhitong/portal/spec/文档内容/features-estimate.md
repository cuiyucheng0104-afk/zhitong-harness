## 一句话

两段式：先从设计说明或可研报告里抽出 11 个规模量的候选值，每个值附原文引文并由脚本回原文核对，这一段不出任何金额；您确认规模量后，脚本按概算模板的公式计算，输出带真实 Excel 公式的《概算.xlsx》。金额全部由脚本计算，模型不算钱。

## 适用场景

- 投资估算、设计概算编制：按规模估总投资，出概算表。
- 想先看看某项工程建设其他费（监理费、设计费、环评费等）按费率规则的参考值。
- 已经有部分成本数，想用公式模板汇总出总投资，并在 Excel 里继续调整。

## 您可以这样说

- "按可研报告做一版设计概算。"
- "先把总建筑面积、地上地下面积、用地面积和车位数从设计说明里找出来，我确认后再算。"
- "B 区地块原文没有，填 0。"
- "监理费按费率规则给个参考值。"
- "预备费率改成 3%。"
- "这版概算为什么标了【草稿】？"

## 需要准备的资料

| 资料 | 说明 |
|---|---|
| 设计说明、可研报告、经济技术指标表 | `.pdf`（文字层）、`.docx` 等；扫描件没有识别文本时，助手先看图把文字写成旁车 `<原件名>.ocr.txt` |
| 项目名称 | 含标段名，例如「滨江综合办公楼」或「某某项目 II 标」；用于判断面积是不是本标段的 |
| 计费基数与属性（可选） | 算工程建设其他费的参考值时需要，例如工程费用（万元）、中标金额、项目所在地区；缺什么由脚本列出，助手逐项问您 |
| 建设用地费（可选） | 出让合同价或挂牌价（万元）；划拨或不计列时请明确说填 0 |

### 11 个必填规模量

全部在模板「经济技术指标」工作表上。原文没有的格也要填，没有就填 0。

| 格 | 名称 | 单位 |
|---|---|---|
| D4 | 用地面积 | ㎡ |
| D7 | A区地下室 | ㎡ |
| D8 | B区地下室 | ㎡ |
| D10 | 1#楼 | ㎡ |
| D11 | 2#楼 | ㎡ |
| D12 | 3#楼 | ㎡ |
| D13 | 构筑物 | ㎡ |
| D15 | 占地面积 > A区地块 | ㎡ |
| D16 | 占地面积 > B区地块 | ㎡ |
| D19 | 地面机动车停车 | 辆 |
| D20 | 地下机动车停车 | 辆 |

总建筑面积 D5 由公式汇总各单体，不手填。单体按原文出现的顺序归入固定槽位（地下室 2 个、地上楼栋 3 个、构筑物 1 个），超出槽位的单体不会被合并或丢弃，而是列为「单体未归位」，由您决定并入哪个槽位。

## 它会怎么做

1. **准备抽取**（`estimate.py extract_prepare`）。脚本写出《概算抽取说明.md》（规则、单体清单、总量、逐格口径与同义词）和每份资料的正文 `概算抽取正文-NN.txt`。正文超过 12,000 字时只给关键词附近的窗口。
2. **助手作答**。助手读完说明再逐份读正文，按说明写 `extract_answers.json`：只抄原文，不换算、不推算；每个值附一段能在原文逐字找到、不超过 40 字的引文；同一项原文有几个不同数就全部列出；不写任何金额。
3. **核对抽取**（`estimate.py extract_finalize`）。脚本解析数值（"万""亿"倍率由代码乘）、用引文回原文核对、把单体归入槽位、把槽位合计与原文总建筑面积对账。
4. **请您确认**。助手用选项卡逐项请您确认或改值：候选值、没找到的格、原文有多个数的格、未归位的单体。只有您确认过的数才进入计算。
5. **正向推算（可选）**（`estimate.py suggest`）。用指标基准的中位数 × 规模，给成本位出建议值，并按费率规则给工程建设其他费出参考值。建议值逐条请您采纳或改写，不会自动写入。
6. **计算与出表**（`estimate.py compute`）。依次过四道拦截闸：必填 → 面积闸 → 面积对账 → 全零。通过后写出《概算.xlsx》。
7. **汇报**。七项合计照抄脚本结果，说明成本位填了多少，以及质量结论。确认后用 `tos_push` 推到项目 `成果/`。

### 示例：2026-007 滨江综合办公楼（示例数据）

以下用示例项目的《竣工图总说明》演示抽取与计算的完整过程。真实概算通常使用可研报告或初步设计说明。

**第 1 步：抽取与核对。** 原文写着：

```text
总用地面积 6850㎡
总建筑面积 18600㎡，其中地上建筑面积 15200㎡，地下建筑面积 3400㎡
建筑占地面积 2740㎡，建筑密度 40%
机动车停车位 110 辆，其中地面停车位 24 辆，地下停车位 86 辆
办公楼 地上 15 层 建筑面积 15200㎡
地下室 地下 1 层 建筑面积 3400㎡
```

`extract_finalize` 给出 6 个候选、5 个未解决项：

| 格 | 名称 | 候选值 | 引文 | 置信 | 说明 |
|---|---|---|---|---|---|
| D4 | 用地面积 | 6850 | 总用地面积 6850㎡ | 1.0 | |
| D7 | A区地下室 | 3400 | 地下室 地下 1 层 建筑面积 3400㎡ | 1.0 | 单体「地下室」 |
| D10 | 1#楼 | 15200 | 办公楼 地上 15 层 建筑面积 15200㎡ | 1.0 | 单体「办公楼」 |
| D15 | A区地块 | 2740 | 建筑占地面积 2740㎡ | 1.0 | 原文只有占地总量、未分区，已放在首位 |
| D19 | 地面机动车停车 | 24 | 地面停车位 24 辆 | 1.0 | |
| D20 | 地下机动车停车 | 86 | 地下停车位 86 辆 | 1.0 | |

| 格 | 名称 | 原因 |
|---|---|---|
| D8 | B区地下室 | `not_found` 原文未提及 |
| D11 | 2#楼 | `not_found` 原文未提及 |
| D12 | 3#楼 | `not_found` 原文未提及 |
| D13 | 构筑物 | `not_found` 原文未提及 |
| D16 | B区地块 | `total_only_no_partition` 原文只有总量，无法分区 |

置信 1.0 表示引文在原文里找到了、数值也在引文里。槽位合计 3,400 + 15,200 = 18,600 ㎡，与原文总建筑面积一致。

**第 2 步：您确认。** 您说："6 个候选都对，其余 5 格填 0，业态是办公。"

**第 3 步：正向推算。** 没有给指标基准文件时，脚本用随包的样本基准，并给出提示：

- 150 个成本位中，34 个有建议值，116 个没有；
- `baselines_default_sample`（info）：用随包样本基准，单一来源；
- `baseline_single_sample`（warn）：样本来源少于 3 个，建议值只作单样本参考，不自动预填；
- `baseline_dims_unasserted`（warn）：基准没有区分地区、价期、结构类型；
- `fee_bases_absent`（warn）：没有计费基数，工程建设其他费本次不出参考值。

建议值示例：「1.建筑工程费!C7 土石方工程（地下室）」数量 3,400 ㎡ × 单方 245.00 元/㎡ = 83.30 万元，样本区间 81.60–85.00 万元。

**第 4 步：计算。** 示例中您把 34 条单样本参考值全部采纳，其余成本位不填，然后计算：

| 合计项 | 单元格 | 值（万元，`result.json` 原值） |
|---|---|---|
| 工程费用（一） | 估概算总表!C5 | 9,290.1311 |
| 工程建设其他费用（二） | 估概算总表!C45 | 0 |
| 工程预备费（三） | 估概算总表!C46 | 464.506555 |
| 建设静态总投资（四） | 估概算总表!C47 | 9,754.637655 |
| 建设期融资费用（五） | 估概算总表!C48 | 未填 |
| 铺底流动资金（六） | 估概算总表!C49 | 未填 |
| 建设动态总投资（七） | 估概算总表!C50 | 9,754.637655 |

质量结论为草稿（`draft`），理由：

- `coverage_below_draft`：成本位只填了 34/150（22.7%），低于 30%；
- `sheet_unfilled_review`：「3.专项工程费」0/42、「5.工程建设其他费用」0/23 一格都没填；
- `reference_values_adopted`：采纳了 34 条单样本参考值；
- `land_cost_unfilled`：建设用地费未填，按 0 计入。

> **注意**
> 示例里的成本位全部来自随包的单样本参考值，所以结果是草稿，不能作为概算结论，也不能与本项目的结算金额对比。示例只用来展示流程和表格。

## 得到什么

`工作/2026-10-20-概算/` 下：

| 文件或目录 | 内容 |
|---|---|
| `extract/` | `result.json`、`概算抽取说明.md`、`概算抽取正文-NN.txt` |
| `extract_answers.json` | 助手的抽取回答 |
| `extract_final/` | 抽取核对结果：`candidates`（候选）、`unresolved`（未解决项）、单体归位 |
| `suggest/` | 正向推算结果（做了才有） |
| `compute_request.json` | 计算请求：您确认的全部格、费率、来源申报等 |
| `result.json` | 计算结果 |
| `概算.xlsx` | 概算表 |
| `待确认清单.md` | 未确认的格、面积差异、需复核理由 |

### 概算.xlsx

10 张工作表：经济技术指标、估概算总表、1.建筑工程费、2.安装工程费、3.专项工程费、4.室外及配套工程费、5.工程建设其他费用、1.1概算建筑项目清单、2.1估概算安装项目清单，以及末页「生成说明」。

- 单元格里是真实的 Excel 公式（共 499 条），例如「估概算总表」C5 是 `=C6+C9+C12+C15+C18+C21+C24+C34`。您在 Excel 里改输入格，合计会自动重算。
- 预备费率单独放在「估概算总表」J46（J45 写「预备费率」），默认 5%。要调费率就改 J46；C46 是公式格，不要改。
- 质量结论不是 `ok` 时，各表标题前加【草稿】或【需复核】。
- 页眉写「AI 初稿·须人工复核」。
- 「生成说明」页列出项目名称、生成时间、模板与口径策略版本、质量结论及理由、项目画像、各表成本位覆盖率和告警。

## 结果怎么读

### 抽取结果

| 字段 | 含义 |
|---|---|
| `confidence` 1.0 | 引文在原文里，数值在引文里 |
| `mapping=semantic` | 凭语义对上的格，请重点核对 |
| `not_found` | 原文没有 |
| `ambiguous` | 原文有多个不同的数，全部列出，由您选 |
| `total_only_no_partition` | 原文只有总量，无法分到 A/B 区 |
| `unmapped_building` | 单体超出槽位，没有归位 |
| `derived` | 推算值（例如用地面积 × 建筑密度推出的占地），不进候选，要您同意才填 |
| `area_total_mismatch` | 槽位合计与原文总建筑面积相差超过 1% |
| `scope_whole_site_suspect` | 项目名称带标段，但原文总面积没有注明是本标段的，可能是全地块的数 |

### 四道拦截闸

被拦时状态为 `insufficient`，`status_reason` 是闸的码，助手转述原因并按它请您补输入。

| 顺序 | 码 | 什么时候拦 | 怎么办 |
|---|---|---|---|
| 1 | `required_inputs_missing` | 11 个必填格有没填的（填 0 也算已填） | 补填；原文没有的填 0 |
| 2 | `area_gate_failed` | 总建筑面积为空或 ≤ 0 | 补填单体面积 |
| 3 | `area_total_mismatch` | 槽位合计与原文总面积相差超过 1% | 把未归位单体并入槽位；确属口径差异（如原文总面积含架空层）时，写明理由确认放行，记为 `area_mismatch_acknowledged` |
| 4 | `all_zero_result` | 建设静态总投资为 0 | 补成本位 |

### 质量结论（`quality.review_level`）

| 值 | 含义 |
|---|---|
| `ok` | 可交付的初稿，仍需人工复核 |
| `needs_review` | 需复核：例如采纳过参考值或仓主放行的费率、面积差异已确认放行、占地缺失、土地费未填、未申报来源、费率采纳值过期 |
| `draft` | 草稿：成本位覆盖率低于 30%，或「1.建筑工程费」「2.安装工程费」任一表一格都没填 |

计算结果的 `status` 为 `ok` 时，`status_reason` 也会写成质量结论（`draft` / `needs_review`），请一并看。

### 合计与覆盖率

- 七项合计照抄 `totals`，助手不自己加减。
- `input_coverage` 说明 150 个成本位填了几个、各表缺多少。未填的成本位按"空格 = 0"参与求值，合计因此偏低（`cost_input_incomplete`）。
- 建设期融资费用、铺底流动资金不填时按 0 计，动态总投资会等于静态总投资（`optional_input_missing`）。

## 需要您确认的事项

> **需人工确认**
> 抽取出的规模量只是候选，确认后才进入计算。所有金额、数量都是待复核的初稿。

1. **每个规模量**：值是否正确、口径是否属于本项目（本标段）。
2. **原文有多个数的格**：助手不会替您选。
3. **单体归位**：超出槽位的单体并入哪个槽位。
4. **推算值**：例如按建筑密度推算的占地面积，同意才填，来源记为推算。
5. **建议值的采纳**：正向推算给出的成本建议值、其他费参考值，逐条采纳或改写。
6. **面积差异放行**：槽位合计与原文总面积不一致时，是否确认放行及理由。
7. **费率属性**：脚本按默认属性计算的费率（例如项目所在地区默认城区、环评按报告书）会提示 `fee_attr_defaulted`，请确认。

## 限制与注意

- **模板是脱敏样本**：`gsyz_v1` 是脱敏后的样本模板（9 张表、515 条公式）；抽取口径是内部口径，未经造价员签字。
- **费率规则未经造价员签署**：`fee_rules_zj2018`（浙江 2018 其他费用定额等 16 项）的签核状态是 `owner_release`，即仓主默认放行，不是造价员签署；393 个转录数值没有经过造价员逐值核对。出参考值时会给出 `fee_rules_owner_released` 告警。
- **勘察设计费单独扣留**：档位闭开性没有确认，该项参考金额一律不出（`fee_suggestion_withheld`）。工程勘察费、工程保险费等没有数值规则的项需要人工填报。
- **指标基准是单一样本**：随包基准只来自一个样本工作簿，建议值只作单样本参考，不自动预填。公司有自己的指标基准文件时（例如知识库里的指标基准），可以让助手改用它。
- **偏离阈值是占位值**：费率参考值给出的上下浮动区间按 ±20%（偏离阈值 0.20）计算，这个阈值未经造价员确认。
- **预备费率**：默认 5%；超出 3%–8% 只提示 `rate_out_of_range`，不拦截。
- **抽取阶段不说金额**：助手在抽取和确认阶段不会说出任何金额。
- **可复现**：计算请求里固定生成时间（`generated_at`）时，同一输入两次出表逐字节一致。

## 常见问题

**问：为什么一定要我确认规模量？**

答：规模量是模型从原文抽出来的候选。只有经您确认的值才进入计算，这样每个金额都能追到您确认过的输入。

**问：原文没写 B 区地下室、2# 楼，为什么还要填？**

答：这 11 个格是模板的必填位，没填会被必填闸拦下。本项目没有的，明确填 0 即可。

**问：概算标了【草稿】是什么原因？**

答：看「生成说明」页和助手转述的质量理由。常见原因是成本位覆盖率低于 30%，或建筑工程费、安装工程费整表没填。补齐成本位后重新计算即可。

**问：能直接改 Excel 吗？**

答：能。表里是真实公式，改输入格会自动重算；改预备费率请改「估概算总表」J46。改完的数字没有经过脚本的拦截闸和质量判断，请自行复核。

**问：项目有 5 栋楼，模板只有 3 个楼栋槽位怎么办？**

答：多出的单体列为「单体未归位」，不会被丢弃。请告诉助手把它们并入哪个槽位；槽位合计与原文总面积相差超过 1% 时会被面积对账闸拦下，提示您处理。

**问：为什么勘察设计费没有参考值？**

答：费率表档位的闭开性没有经过造价员对原图确认，落在档界上的基数会算出不同金额。为避免编出一个金额，该项一律扣留，请人工填报。
