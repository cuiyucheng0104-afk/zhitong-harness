## 一句话

按项目目录和文件名读取或新建项目说明，对照资料清单列出缺件和待确认的资料；缺件结论由您核实后再对外使用。

## 适用场景

- 造价工程师接到新项目：分配项目编号，建好目录，写项目说明，并在案例索引里登记一行。
- 造价工程师接手同事的项目：先读项目说明，知道合同、计价表、图纸放在哪里，再开始工作。
- 从旧系统迁来、没有项目说明的项目：按目录结构生成项目说明草稿，再逐项核对。
- 开始核对、写报告之前：盘点资料，弄清缺什么、哪些只是"疑似已备"。
- 审核负责人检查项目准备情况：看项目说明里的"资料盘点"小节和待确认事项。

## 您可以这样说

- "新建一个项目：滨江综合办公楼，结算审核，审定阶段，办公楼，建筑面积 18600 平方米，合同号 HT-DEMO-07。"
- "打开 2026-007，告诉我关键文件都在哪。"
- "2026-007 的资料齐不齐？缺什么？"
- "签证单汇总那份你打开看一下，是不是变更签证费用的资料。"
- "这个项目没有项目说明，按目录帮我生成一份草稿。"
- "把这次盘点的结论写进 2026-007 的项目说明。"

## 需要准备的资料

项目资料都放在公司的火山引擎对象存储（TOS）里，下文称"公司存储桶"。表中路径都从公司前缀开始写。使用前须已导入配置包：配置包是服务方按贵司环境整理的压缩文件，含公司存储桶的地址、区域、桶名、目录前缀、访问密钥和公司名，见[导入配置包](/docs/config-package/)。

| 资料 | 放在哪里 | 格式要求 | 必需或可选 |
|---|---|---|---|
| 新项目的基本信息 | 在对话里告诉它 | 工程名称；咨询类型三选一：全过程造价咨询、结算审核、招标控制价编制；阶段五选一：概算、招标控制价、施工过程、结算、审定 | 新建项目时必需 |
| 业态、规模、客户合同号 | 在对话里告诉它 | 合同号记在项目说明的"别名"里，不进目录名 | 可选 |
| 案例索引 | 公司存储桶根目录 `案例索引.md` | 每个项目一行；桶里还没有时按模板新建 | 新建项目时使用 |
| 项目说明 | `项目/<编号>-<工程名>/项目说明.md` | Markdown，开头是字段区；咨询类型、阶段不能是"待确认" | 打开已有项目时必需；没有可生成草稿 |
| 客户资料 | `项目/<编号>-<工程名>/资料/` | 任意格式；盘点只看文件名和所在目录 | 盘点时必需 |
| 图纸 | `项目/<编号>-<工程名>/图纸/` | DWG 等；盘点只看文件名，不下载 | 可选 |

> **提示**
>
> 文件名越规范，盘点越准。"结算送审书.pdf"能直接判定类目；"新建文本文档.txt""扫描件0001.pdf"判不出，只能打开看。

## 它会怎么做

### 新建项目

1. 拉取最新的案例索引 `tos_pull 案例索引.md`，列出桶里已有的项目目录 `tos_ls 项目/`。
2. 用确认提问 `ask_user_question` 问清工程名称、咨询类型和阶段；业态、规模、合同号可以一并给出。
3. 分配编号 `new_project.py allocate`：编号格式是 `YYYY-NNN`，即建项目年份加当年三位流水号，取案例索引和桶内 `项目/` 目录中当年最大流水号加一，不补空洞，跨年从 001 起。它把编号和目录名告诉您，请您确认。
4. 建项目 `new_project.py create`：在本机建好 `资料/`、`图纸/`、`工作/`、`成果/` 四个子目录，写项目说明（状态"进行中"），在案例索引末尾追加本项目一行。
5. 立即推送 `tos_push` 项目说明和案例索引两个文件。推送成功后编号才算占住。如果回读提示"拉取后别人改过"（`remoteChangedSincePull`），说明同事同时开了项目：它会重新拉取案例索引、删掉本机刚建的目录、回到第 3 步重新分配。

### 打开已有项目

1. 列目录 `tos_ls 项目/`，按工程名匹配；有多个候选时列出来问您，不替您选。
2. 拉取项目说明 `tos_pull`，读取 `project_doc.py show`。
3. 向您转述编号、工程名、咨询类型、阶段、关键文件指引和已出成果。
4. 字段缺失或仍是"待确认"时，结果为资料不足（`insufficient`），它会先问您，改好项目说明再继续，不猜。
5. 之后按"关键文件指引"一次只拉一份需要的文件，不整目录拉取，也不拉图纸。

### 项目没有项目说明

1. 把项目目录拉到本机（至少让目录结构可见），生成草稿 `project_doc.py draft`。
2. 草稿从目录名取编号和工程名，"目录概览"列出各子目录的文件数，"关键文件指引"按文件名填候选路径并备注"按文件名判断，待确认"，咨询类型和阶段写"待确认"。
3. 它问您咨询类型和阶段，并逐个打开候选文件核对，核对过才去掉"待确认"，然后推送项目说明。
4. 草稿不会覆盖已有的项目说明。

### 资料盘点

1. 列全文件 `tos_ls`（递归、翻页），每个路径一行写到 `工作/<日期>-盘点/文件清单.txt`。图纸不下载。
2. 运行盘点 `inventory.py scan`：咨询类型和阶段默认取项目说明里的值。两处都没有阶段时先问您；只有您明确要求时才按全部阶段核查。
3. 转述摘要：必备项总数、已备、待确认、缺失，齐备率及其上限。
4. 对"待确认"的资料，打开候选文件确认（Office 和 PDF 读正文，扫描件用看图 `read_image`），确认前只说"疑似已备"。
5. 报缺件之前，先看"没判出类目的文件"里有没有同类资料。
6. 把结论写进项目说明的"资料盘点"小节：日期、依据的咨询类型与阶段、缺件、待确认事项；再推送项目说明。

### 示例：开 2026-007 并盘点（示例数据）

以下对话与结果均为示例数据。2026-10-19，造价工程师说："新建一个项目：滨江综合办公楼，结算审核，审定阶段，办公楼，建筑面积 18600 平方米，合同号 HT-DEMO-07。"

1. 工具调用条依次出现：拉取文件 `tos_pull 案例索引.md`、列目录 `tos_ls 项目/`、分配编号 `new_project.py allocate`。
2. 它回复："案例索引和桶内目录里 2026 年最大编号是 2026-006，新项目编号 2026-007，目录名 `2026-007-滨江综合办公楼`。按这个建吗？"您选"确认"。
3. 建项目 `new_project.py create`，推送 `tos_push` 两个文件，回读一致。编号占住。
4. 资料放进 `资料/` 后，您问："2026-007 的资料齐不齐？"它列出 13 个文件，运行盘点 `inventory.py scan`，回复：

```text
资料盘点（结算审核，审定阶段，按概算至审定五个阶段累计）· 示例数据
状态：完成（ok）
必备 7 项：已备 3，待确认 1，缺失 3
齐备率 42.86%（3/7）；待确认那项核实后最高 57.14%（4/7）

已备：施工合同及补充协议（资料/1 合同及协议/施工合同及补充协议.docx）
      竣工图纸（资料/3 竣工资料/竣工图/竣工图总说明.pdf）
      结算送审书（资料/4 结算资料/结算送审书.pdf）
待确认：变更签证费用 ← 资料/5 变更资料/签证单汇总.xlsx（只靠目录名推断）
缺失：结算审核报告、结算审定单、审核汇总表（审定阶段）
重要项：施工图纸（图纸/A-02 二层平面图.dwg）、工程量清单已备；
        招标控制价文件 ← 资料/2 招标资料/招标文件.pdf，待确认；
        投标报价文件未找到（只提示，不影响齐备率）
没判出类目：资料/6 其他/扫描件0001.pdf
不计入：施工日志.docx（非造价资料）、扫描件0001.pdf.ocr.txt（识别文本旁车）
```

5. 它接着说明：结算审核的清单把结算审核报告、结算审定单、审核汇总表列为审定阶段必备项，本项目这三份正是待出的成果，放进 `成果/` 后再盘点即算已备。送审计价表和审定计价表被归为"结算价文件"，清单里没有这一项，不参与盘点，它们是[送审审定核对](/docs/features/check/)的输入。
6. 它打开 `签证单汇总.xlsx` 看过内容后，问您是否按"变更签证费用已备"记录；您确认后，结论写进项目说明并推送。

## 得到什么

```text
项目/
  2026-007-滨江综合办公楼/
    项目说明.md            # 新建时生成；盘点结论写进「资料盘点」小节
    资料/                  # 客户原件，由您或同事放入
    图纸/
    工作/
      2026-10-19-盘点/
        文件清单.txt       # 盘点时列出的全部文件路径

    成果/

```

本机缓存与公司存储桶同构：`~/zhitong/项目/2026-007-滨江综合办公楼/`（Windows：`%USERPROFILE%\zhitong\项目\2026-007-滨江综合办公楼\`）。

| 文件 | 内容 | 谁会用到 |
|---|---|---|
| `项目说明.md` | 开头字段区（编号、工程名称、咨询类型、阶段、业态、规模、别名、状态、建立日期），正文分基本信息、关键文件指引、资料盘点、已出成果、工作记录五节；草稿另有"目录概览" | 所有能力开工前先读它；接手的同事先读它 |
| `案例索引.md` | 每个项目一行：编号、工程名、业态、规模、咨询类型、关键指标、成果链接、状态 | 分配编号、[造价指标](/docs/features/metrics/)对标、[归档](/docs/features/archive/) |
| `文件清单.txt` | 盘点依据的文件路径清单 | 复查盘点范围 |
| `result.json` | 盘点完整结果：已备、待确认、缺失、仅提示、未判出类目的文件 | 需要明细时查看 |

示例项目说明的字段区：

```text
---
项目编号: "2026-007"
工程名称: "滨江综合办公楼"
咨询类型: "结算审核"
阶段: "审定"
业态: "办公"
规模: "建筑面积 18,600.00 m²"
别名: ["合同号 HT-DEMO-07"]
旧系统项目ID: ""
状态: "进行中"
建立日期: "2026-10-19"
---
```

新建项目的"关键文件指引"是空的。您可以告诉它某份资料的位置，请它写进去；这里只写打开核对过的路径。

盘点不给文件改名，不打标签，也不把分类结果写进任何文件。

## 结果怎么读

状态与告警的通用含义见[结果状态与告警](/docs/results/)。本能力特有的读法：

| 结果 | 含义 | 您要做什么 |
|---|---|---|
| 完成（`ok`） | 盘点正常结束，告警逐条列出 | 看缺失和待确认两类 |
| 资料不足（`insufficient`，`no_categorized_files`） | 一个文件都判不出类目 | 缺件清单不可信，不要当成"全缺"；检查目录是否拉全、文件名是否规范 |
| 资料不足（`insufficient`，`project_doc_incomplete`） | 项目说明缺必填字段或仍是"待确认" | 告诉它正确的值 |
| 警告 `required_item_missing` | 必备资料没找到 | 先看"没判出类目的文件"，确认没有再向客户要 |
| 警告 `required_item_unconfirmed` | 必备资料只有弱证据 | 让它打开候选文件确认 |
| 提示 `important_item_missing` | 重要资料没找到 | 知悉即可，不影响齐备率 |

几个数字怎么算：

- 齐备率 = 已备 ÷ 必备项总数；上限 = （已备 + 待确认）÷ 必备项总数。示例中 3 ÷ 7 = 42.86%，4 ÷ 7 = 57.14%。
- 齐备率显示为空时表示没有可算的比率，不是 0，也不是 100%。
- 只有必备项进分母。重要项缺了只提示；可选项（如造价指标分析）只在明细里列出。

已备与待确认的区别：

- 已备：文件名命中具体规则，例如"施工合同""结算送审""工程量清单"、带类目的"竣工图"、DWG 按专业判定。
- 待确认：只命中"签证""招标"这类单个词，或者靠所在目录名推断。示例中"签证单汇总.xlsx"本身不含特指词，是从目录"5 变更资料"推断的。
- 文件名判为工程量清单、招标控制价，但所在目录名含"进度款、产值、付款、支付、结算、审核终稿、套价"时，降为待确认：那多半是某一期的过程文件。

清单口径：

- 阶段按累计计算：选"审定"时，概算、招标控制价、施工过程、结算、审定五个阶段的清单项都算；选"施工过程"时算前三个。
- 结算审核、招标控制价编制有专属清单（分别 12 项、4 项）；全过程造价咨询用通用清单（20 项）。三套共 36 项。
- 同一份文档的 `.doc` 与 `.docx`、`.xls` 与 `.xlsx` 只算一份。
- `工作/` 下的中间产物不参与盘点；`成果/` 下的文件参与。

## 需要您确认的事项

> **需人工确认**
>
> - 新项目的编号和目录名：推送前确认，推送后才占住编号。
> - 咨询类型和阶段：它们决定用哪套清单、算哪些阶段。
> - 每一项"待确认"的资料：打开看过才能记为已备。
> - 每一项"缺失"的资料：先排除"没判出类目的文件"里有同类资料，再向客户要件。
> - 草稿"关键文件指引"里的每个候选路径。2026-007 的草稿把 `资料/4 结算资料/结算送审书.pdf` 填进了"送审计价表"一栏，真正的送审计价表是 `资料/4 结算资料/送审计价表.xlsx`。
> - 盘点所依据的资料清单和分类规则本身：它们尚未签核，见下一节。

## 限制与注意

- 资料清单与文件名分类规则从旧系统迁来，整体待签核。清单每一项都标有签核状态（`seed` 旧系统出厂值、`provisional` 业务方暂定、`unconfirmed` 客户未确认），没有任何一项是"客户已确认"。对客户不要说"按客户确认的清单"。
- 盘点只看文件名和目录，不读内容。文件叫"结算审定单"不等于它真是审定单；需要核实就打开。
- 扫描件、`IMG_0001.jpg`、"新建文本文档"这类名字判不出类目，会进"没判出类目的文件"，默认最多列出 100 个。
- 分类规则按旧系统客户的命名习惯调出来。贵司命名习惯不同时漏判会增多。口径需要调整时，由负责维护的同事修改规则文件，不在对话里临时改。
- 编号分配不加锁：两人同时开项目时，后推送的一方在回读时发现冲突并重新分配。推送前编号只在本机，不算占住。
- 当年流水号用到 999 后无法再分配，需要先改编号规则。
- 目录名里的工程名会去掉空格和 `/\:*?"<>|`；客户的合同号、内部编号写进"别名"。
- 盘点不下载图纸。看图纸内容用 [CAD 看图](/docs/features/cad/)。
- 盘点的确认结果写在项目说明里；`result.json` 里的齐备率不会因人工确认而改变。

## 常见问题

### 为什么刚开项目，结算审核报告、结算审定单、审核汇总表就显示缺失？

结算审核项目的资料清单把这三项列为审定阶段的必备项。项目刚开始时它们还没做出来，所以显示缺失。做完并放进 `成果/` 后再盘点，就会算已备。这是清单本身的口径，清单尚未签核，贵司如需调整，请负责维护的同事修改清单文件。

### 齐备率 42.86% 是不是说明资料很不全？

不一定。示例中 7 个必备项里，3 个是本项目待出的成果，1 个只是待确认。真正需要向客户要件的，要看"缺失"清单逐项排除后的结果。齐备率只作参考，结论以您核对后写进项目说明的内容为准。

### 文件明明在，为什么显示"待确认"？

文件名只命中了一个泛称，或者类目是从目录名推断的，属于弱证据。请它打开文件看一眼；您确认后，它会在项目说明里记为已备。

### 盘点会不会给我的文件改名、打标签？

不会。盘点只读文件名和目录，不改名，不移动，不打标签，也不把分类结果写进文件。它只写 `工作/<日期>-盘点/` 下的两个文件和项目说明的"资料盘点"小节。

### 两个同事同时新建项目，会撞号吗？

可能在本机算出同一个编号，但推送时会发现。先推送的一方占住编号；后推送的一方回读时看到案例索引已被改过，会重新拉取、重新分配。所以建项目后要立即推送。

### 项目说明里的字段写错了怎么改？

直接告诉它正确的值，它会改项目说明的字段区并推送。您也可以自己编辑 `项目说明.md` 的字段区，保持"字段: 值"一行一个。改咨询类型或阶段后，请重新盘点。
