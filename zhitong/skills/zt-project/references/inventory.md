# 资料盘点：判定顺序、证据级别、清单口径

给想弄清「为什么这份算已备 / 为什么这份没算」的人看。代码在 `zhitong/python/zt/inventory/`，数据在本 skill 的 `data/`。旧系统出处写在各数据文件头；整套规则与清单**待签核**。

## 分类（文件名 + 祖先目录）

规则文件 `classify_rules.yaml` 按下面的顺序判，命中即停：

1. 噪音（未命名、标段号）→ 不判。
2. 系统生成物（`INDEX.md`、`*.ocr.txt` 旁车）→ 不是资料，不参与盘点。
3. 黑名单（施工日志、监理月报、资质证书…）→ 跳过；同时命中升档词（结算、签证、合同价…）则白名单胜出；名字里带造价疑词又没有升档词的，跳过但标待复核。
4. 扩展名：图纸（dwg）按文件名里的专业词归到各类图纸；广联达等计价文件类目按目录推断。
5. 复合白名单（`审核+报告`、`工程量+清单`…）→ 6. 特指白名单（`施工图预算`、`结算送审`…）→ 7. 带类目的归档词（`竣工图`、`图纸会审`…）→ 8. 设计文档 / CAD 细分 → 9. 直属父目录是专业词 → 10. 祖先目录继承 → 11. 白名单裸词（`招标`、`签证`、`结算`…）→ 12. 只命中无类目专业词（`建筑`、`市政`）→ 13. 默认跳过待人工归档。

目录语境只用已剔除容器根（`资料/`、`图纸/`、`成果/`）的祖先目录，由近及远。

## 证据级别

| 级别 | 来源 | 盘点里的待遇 |
|---|---|---|
| strong | 文件名命中特指 / 复合 / 带类目归档词 / 设计文档 / 扩展名规则（`filename_rule`） | 算「已备」，进分子 |
| weak | 文件名只命中裸词、靠祖先目录继承、父目录是专业词 | 算「待确认」，不进分子，需要打开确认 |
| confirmed | 人工确认过 | 盘点脚本目前不产生；预留给确认后的重新核查 |

强证据在冲突目录下降为 weak：类目是工程量清单 / 招标控制价 / 合同价款约定，而目录段里有「进度款、产值、付款、支付、结算、审核终稿、套价」（`audit_evidence_rules.yaml`）——那是某一期的过程文件，不是招标阶段的那份。

## 清单口径

- 类目先经 `doc_category_map.yaml` 折算再比对：建筑图纸、结构图纸、设计图纸…→ 施工图；结算审定书 / 审定稿 → 审定单；结算送审稿 → 结算送审书；招标文件是招标控制价项的别名。登记在 `not_audited` 的类目（竣工验收报告、监理合同…）不参与盘点。
- 咨询类型：结算审核（20002）和招标控制价编制（20003）有专属清单，全过程造价咨询（20001）用通用清单。
- 阶段累计：选「审定」= 概算、招标控制价、施工过程、结算、审定五个阶段的清单项都算；选「施工过程」= 前三个。分母只算必备项（`required`），重要项缺了只提示，可选项只在 `optional_missing` 里列出。
- 清单项有阶段、文件也判出了阶段时要求一致；任一侧没有阶段时只比类目，`summary.degraded_matches` 记下这种降级命中的项数。
- 同一份文档的 `.doc` 与 `.docx`、`.xls` 与 `.xlsx` 只算一份。

## 已知局限

- 只看文件名：扫描件、`IMG_0001.jpg` 这类名字判不出的资料只能进 `unclassified_files`，靠人或 `read_image` 判断。
- 规则按旧系统客户的命名习惯调出来的；换了公司，命名习惯不同，漏判会多。改 `classify_rules.yaml` 即可，改完跑 `tests/inventory`。
- 清单里的 `signoff` 字段写着每条的签核状态（`seed` / `provisional` / `unconfirmed`），没有任何一条是「客户已确认」。
