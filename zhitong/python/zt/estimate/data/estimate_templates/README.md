# 概算模板种子：gsyz_v1_template.xlsx

## 这是什么

《房屋建筑工程概算指引》脱敏模板，作为概算引擎的模板种子入仓。
原件来源为客户提供的工作底表（WPS 制作，含真实项目数据），已于 2026-08-29 完成脱敏（spec 条目 I-0.1）。

- 9 个 sheet：`经济技术指标` / `估概算总表` / `1.建筑工程费` / `2.安装工程费` / `3.专项工程费` / `4.室外及配套工程费` / `5.工程建设其他费用` / `1.1概算建筑项目清单` / `2.1估概算安装项目清单`
- 515 条公式全部原样保留（脱敏前后逐格字符串比对一致）
- 211 个纯输入数值单元格已全部清空（留空，不是填 0——公式对空格按 0 计算）
- 结构保真：合并单元格 64 处、行列结构、序号、计量单位、章节结构、列宽、大纲分组均未动

## 515 条公式的 8 类归纳

| 类 | 模式 | 条数 | 示例 |
| --- | --- | --- | --- |
| 1 | SUM 区段聚合 | 30 | `=SUM(C7:C13)` |
| 2 | 加总链（+） | 15 | `=C6+C15+C24+…` |
| 3 | 跨表单格引用（汇总表←分析表 / 数量←经济技术指标） | 215 | `='1.建筑工程费'!C5`、`=经济技术指标!$D$5` |
| 4 | 单方指标（费用/数量×10000） | 224 | `=C5/E5*10000` |
| 5 | 占比（除法） | 12 | `=C5/C50` |
| 6 | 差额（−） | 1 | `经济技术指标!D17 =D4-D14` |
| 7 | 复合算式 | 2 | `估概算总表!C46 =(C5+C45)*0.05`（预备费）、`5.工程建设其他费用!C5 =C6+C9+SUM(C14:C30)` |
| 8 | DISPIMG 图片函数（WPS 私有） | 16 | `=_xlfn.DISPIMG("ID_…",1)` |

其中 202 条为共享公式（shared formula），openpyxl 载入时已展开为等价的逐格公式，语义不变。

## 原表已知的 3 个缺陷（引擎侧需修正/防御）

1. **F30 错引**：`估概算总表!F30`（交通专项工程的数量）写的是 `='3.专项工程费'!E35`（体育专项的区域面积，与 F28 重复），应为 `E46`。序列可对照：F26→E19（医疗）、F27→E29（教育）、F28→E35（体育）、F29→E42（工业）、F31→E47（演艺）。
2. **哨兵行 SUM 包含性不一致**：各费用 sheet 的分区末尾有 `……` 哨兵行（预留扩展行），部分小计 SUM 的区间包含哨兵行、部分不包含，扩展行数时须逐条核对 SUM 区间，不能按统一规则平移。
3. **序号 float 塌缩**：A 列序号是数值型，`1.10` 存成 float 后塌缩为 `1.1`（与 1.1 无法区分），且存在 `8.199999999999999` 之类浮点误差。引擎生成序号时应改用文本型或独立编码列。

## fee_images/（16 张定额扫描图 + image_map.json）

`5.工程建设其他费用` 的 I 列通过 WPS 私有 `DISPIMG` 函数内嵌了 16 张《浙江省建设工程其他费用定额（2018 版）》扫描页——**公开出版物，不含客户信息，故保留**。

因 DISPIMG 是 WPS 私有机制（`xl/cellimages.xml` + `xl/media/`），openpyxl 重存后该部件不再随 xlsx 携带（I 列的 16 条 DISPIMG 公式字符串仍在，但图片实体已剥离）。图片已单独提取到本目录 `fee_images/image1..16.png`（与原件逐张 MD5 一致），映射关系见 `fee_images/image_map.json`：图片文件名 ↔ DISPIMG ID ↔ 单元格（I6…I30）↔ 费用项名称（如 image1 ↔ I6 ↔ 项目建设管理费）。

## gsyz_v1.json —— 固化引擎模板（I-2.1，2026-08-29）

`gsyz_v1.json` 由 `scripts/build_estimate_template.py` 从本目录脱敏 xlsx **确定性生成**
（重跑字节级一致），是求值器 `app/engine/estimate_engine.py`（I-2.2）的唯一模板输入：

- 9 sheet 三级行树（`row_tree_levels`：节/单位工程/明细）+ 合并/冻结/大纲/列宽元数据
  （`force_expand_outline: true`——原表大量行存成折叠隐藏态，导入必须强制展开）；
- 211 个输入位声明（`inputs`，坐标与上文清单一致）+ 4 个可选输入位
  （`optional_inputs`：总表 C48/C49 融资费用与铺底流动资金及其占比列，原表恒空）；
- 515 条公式（`formulas`，8 类归类同上文）；预备费率参数化（`rate_params.reserve_rate`，
  默认 5%、软区间 3%~8% 只出 warning、1% 可算——费率可调不写死，用户裁决）；
- 上文 3 个缺陷已在 JSON 内修正并留痕（`fixes`，含逐格 before/after）：
  F30 错引 E35→E46（运行时随 warnings 披露）；哨兵行 SUM 统一为**含哨兵行**（扩围
  12 处，原表哨兵格全空、值中立；4.室外行32 表级哨兵的父公式是加链、不动，记为
  known_gap）；序号按行序+层级重建为字符串（53 处，含清单表 float 塌缩 `1.10` 复原）。

### ⚠ `gsyz_v1_template.xlsx` 现在还是「修正前形态」的证据来源（#131）

本目录的脱敏种子保留的是**三处修正之前**的公式（实测 13/13、515/515 精确匹配）。
`tests/test_estimate_template_fixes.py` 拿它当证据源，在 CI 里无条件校验：

- 515 条公式与种子逐字符一致（fixed 格取 `fixes[].changes[].before`，其余取 after）
- F30 错引由两条独立结构不变量各自指认（同行三列引用一致性 / 引用不重不漏）
- 哨兵格值中立前提、53 条序号 before

**改动这个 xlsx 会同时打红那几条闸** —— 那是有意的：它不再只是"生成模板的原料"，
还是"当初原表长什么样"的唯一入仓凭据。要重新脱敏/替换种子，请连带复核那份测试。
