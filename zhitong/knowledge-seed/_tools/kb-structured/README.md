## 写法（为什么长这样）

由引擎 `engine-service/app/filetree/tools.py`（@33601ca8）的检索口径倒推：

- GREP 按行匹配、每条命中只回约 200 字片段 → **一码一行**，「编码｜名称｜单位｜版本」放在行首，单元格内不换行，`|` 转义。
- DOC 单次最多 16000 字 → 单文件超过 16000 字按章再拆（K8 全文、K9 对照表按方案保留单文件，分段读）。
- OUTLINE 最多 200 个标题 → 每个文件标题 ≤ 200。
- 引擎看不到 UI 类目（落盘按日期分目录）→ **类目和版本写进文件名**；文件名 ≤ 60 字、不含 `| / \ < > : " ? * ; ,`。
- 每个文件开头是引用块文件头：来源路径、commit、源 sha256、生成时间、生成脚本、固定声明
  「本文件由脚本从受控源确定性生成，不含任何金额；引用编码必须注明版本（浙江2025 / 国标2013）」。

## 重新生成与核对

它在 `origin/main` 上（#785 的合并提交），**不在 dev 的祖先链上**：`--single-branch`、浅克隆、只 fetch 了 dev 时取不到，
`build_all.py` / `check_kb.py` 开头会先查并以退出码 2 给出补取命令（`git fetch origin main`，浅克隆再加 `--unshallow`）。

### 类目 id 不入仓

知识库类目（`knowledge_category`）的 id 是运行时生成的雪花 id，**每个租户、每个环境都不同**，仓里只记类目名。
上传前把目标租户的两个类目 id 写进本地配置（放 `local_only/`，已 gitignore），再带上它跑一遍校验，manifest 里才会有 categoryId：

```bash
# local_only/categories.json：{"清单": "<该租户「清单」类目 id>", "清单/房屋建筑": "<「清单/房屋建筑」类目 id>"}
python3 check_kb.py --categories local_only/categories.json
```

不给 `--categories` 时 manifest 里 categoryId 记 null；给了就核对键正好是这两个类目名、id 是正整数串（≤ 19 位）且互不相同，
回读时另读一遍配置逐条核对。`mutate_check_kb.py` 另有两组对照（不注入缺陷时，不给配置、给形态合法的假配置都必须全过）。
